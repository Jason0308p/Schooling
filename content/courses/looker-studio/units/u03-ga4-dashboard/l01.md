## 建立標準 GA4 監控儀表板

一個好的 GA4 儀表板應該在 30 秒內回答三個問題：**整體流量健不健康？哪些渠道帶來最多轉換？轉換漏斗哪個環節流失最嚴重？** 這堂課帶你從空白報表開始，逐區塊建出這個儀表板。

> [!BIZ] 為什麼不直接用 GA4 後台？
> GA4 後台報表無法客製化版面、無法整合其他平台數據、也不容易分享給非 GA4 帳號的主管或客戶。Looker Studio 解決了這三個痛點，讓你用一個儀表板涵蓋所有人的需求。

---

## 儀表板架構規劃

標準 GA4 監控儀表板建議分三個區塊：

1. **頂部概覽列**：4–5 個 Scorecard（關鍵指標一眼看）
2. **中間趨勢圖**：Sessions Trend 折線圖（識別週期與異常）
3. **底部明細表**：流量來源分析 + 轉換漏斗數據

---

## 區塊一：頂部概覽列（Scorecard）

### 設定步驟

1. 進入報表編輯模式（右上角「編輯（Edit）」按鈕）
2. 點選「插入（Insert）」→「計分卡（Scorecard）」，在頂部區域拖曳出一個方塊
3. 右側「設定」分頁，**指標**選擇「Sessions」
4. 開啟「**比較日期範圍**」→ 選「上一個時段（Previous period）」
5. 複製這個 Scorecard（Ctrl+C / Ctrl+V），共建立 4 個，依序設定指標為：
   - **Sessions**（工作階段數）
   - **Active users**（活躍使用者）
   - **Key events**（關鍵事件數，需先在 GA4 標記關鍵事件）
   - **Engagement rate**（互動率）

6. 調整 Scorecard 大小讓四個並排在頂部同一列

> [!TIP] 實務建議
> Scorecard 建議加上「緊湊標籤（Compact numbers）」：1,234,567 顯示為 1.2M，讓數字更容易閱讀，特別是在行動裝置上查看報表時。設定位置在「樣式」分頁 → 「數值格式」。

---

## 區塊二：Sessions Trend 趨勢圖

### 設定步驟

1. 點選「插入」→「時間序列（Time series）」，在概覽列下方拖曳出較大的圖表區域
2. **時間維度**：選「Date」（日粒度）
3. **指標**：選「Sessions」；若想同時顯示「Active users」，再新增一個指標
4. 在圖表左上角或報表頂部，插入「**日期範圍控制項（Date range control）**」：
   - 路徑：插入 → 日期範圍控制項
   - 預設範圍建議設為「**過去 28 天（Last 28 days）**」
5. 確認圖表有有效的日期範圍維度，日期範圍為 Auto 且在控制項作用範圍內；同一控制項可同時控制 GA4、Ads 等不同來源，不要求同一資料來源

### 加入裝置比較（可選）

1. 在時間序列圖的「設定」分頁，找到「**比較維度（Breakdown dimension）**」
2. 選擇「Device category」
3. 圖表會變成三條線（mobile / desktop / tablet），方便比較不同裝置的流量趨勢

> [!WARN] 常見問題
> 如果日期範圍控制項無法影響某個圖表，檢查圖表的「**資料範圍（Data range）**」是否設定為「自動（Auto）」。如果圖表的日期範圍被硬設定（例如固定為 2024-01-01 到 2024-12-31），控制項就無法覆蓋它。

## 區塊三：轉換漏斗

### 先區分事件量與序列漏斗

Looker Studio **已有內建 Funnel chart**，不需付費社群元件。圖表只視覺化輸入的步驟與數值，不會自動判定同一使用者依順序完成事件。

### 可操作的事件量概覽

1. 插入 Table 或內建 Funnel chart，資料來源選 GA4。
2. 維度選 `Event name`，指標選 `Event count`。
3. 圖表篩選器只保留 `view_item`、`add_to_cart`、`purchase`，先確認網站有正確送出這些事件。
4. 設定排序並檢查顯示順序；預設按指標大小排序不一定等於業務步驟順序。若需固定步驟序號，可先在上游整理步驟表。
5. 標題註明「各事件發生次數（非序列漏斗）」。重複觸發會增加事件數，不同事件也可能來自不同使用者，不可把相鄰事件量的比例稱為序列轉換率。

### 真正的序列漏斗

到 GA4「探索 → 漏斗探索」定義使用者步驟、開放或封閉漏斗、直接或間接跟隨、時間限制。若要在 Looker Studio 呈現，先在上游依相同使用者、順序及時間窗計算每步人數，再把結果接入圖表；原生 GA4 連接器不會直接重現探索設定。

> [!WARN] 不要混用分母
> Sessions、Event count、使用者數是不同口徑，不能直接組成精確的步驟轉換率。GA4 的 Session key event rate 是含關鍵事件的工作階段比例，也不等於購物事件的逐步序列完成率。

## 區塊四：流量來源分析

### 設定步驟

1. 點選「插入」→「長條圖（Bar chart）」
2. **維度**：「Session source / medium」（顯示 source/medium 組合，例如 `google / cpc`）
3. **指標**：「Sessions」
4. **排序**：Sessions DESC（最多流量在最上方）
5. 在「設定」分頁的「列數限制（Row limit）」設為 10（只看 Top 10 來源）

### 同步加入一個 Table 呈現轉換數據

1. 在長條圖旁邊插入一個 Table
2. **列維度**：「Session source / medium」
3. **指標**：Sessions、Key events、Session key event rate
4. 在樣式分頁將「Session key event rate」的欄位類型設為 Heatmap

> [!BIZ] 為什麼要同時放長條圖和表格？
> 長條圖讓讀者快速看到流量排名，表格讓讀者查閱精確數字和轉換率。兩者互補：圖表負責「概覽」，表格負責「細節」。這個組合在 GA4 報表設計中是業界標準做法。
