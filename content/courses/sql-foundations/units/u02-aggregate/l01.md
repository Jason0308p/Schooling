## 從明細到數字

到目前為止，查詢結果都是一筆一筆的明細。但主管要的通常是**一個數字**：「上個月營收多少？」「有幾個會員？」這時要用**彙總函數（aggregate function）**，把很多列壓成一個值。

| 函數 | 作用 | 範例 |
|---|---|---|
| `COUNT(*)` | 算有幾列 | 訂單數 |
| `COUNT(欄位)` | 算該欄位**不是 NULL** 的有幾列 | 有填城市的會員數 |
| `COUNT(DISTINCT 欄位)` | 算有幾個**不重複**的值 | 有下單的會員數 |
| `SUM(欄位)` | 加總 | 營收 |
| `AVG(欄位)` | 平均 | 客單價 |
| `MIN(欄位)` / `MAX(欄位)` | 最小、最大 | 第一筆訂單日期 |

```sql run
SELECT
  COUNT(*)          AS order_count,
  SUM(total_amount) AS revenue,
  AVG(total_amount) AS avg_order_value
FROM orders
WHERE status = 'completed';
```

WHERE 會**先**篩選，彙總函數再對剩下的列計算。所以上面是「已完成訂單」的訂單數、營收、平均客單價。

## COUNT 的三種寫法，結果不一樣

```sql run
SELECT
  COUNT(*)                    AS all_rows,
  COUNT(city)                 AS has_city,
  COUNT(DISTINCT city)        AS distinct_cities
FROM customers;
```

- `COUNT(*)`：全部列數。
- `COUNT(city)`：city 不是 NULL 的列數，所以比 `COUNT(*)` 少。
- `COUNT(DISTINCT city)`：有幾種不同的城市（NULL 不算）。

> [!BIZ] 「會員數」到底是哪一個數字？
> 面試和實務上很常考：**「下過單的人數」**要用 `COUNT(DISTINCT customer_id)`，不是 `COUNT(*)`。後者算的是訂單數，一個人下 5 單就會被算 5 次。用 GA4 的術語來說，這就是「使用者數」跟「事件數」的差別。

## 彙總函數會忽略 NULL

`SUM`、`AVG`、`MIN`、`MAX`、`COUNT(欄位)` 全都會**跳過 NULL**。這有時候是你要的，有時候會讓你算錯：

```sql run
SELECT
  AVG(birth_year)  AS avg_birth_year,
  COUNT(*)         AS total,
  COUNT(birth_year) AS filled
FROM customers;
```

平均出生年只用「有填」的人計算。如果你想把沒填的當 0（通常不合理）或想知道有多少人沒填，就要特別處理。

> [!WARN] 平均值的分母
> `AVG(x)` = `SUM(x) / COUNT(x)`，分母是**非 NULL** 的筆數，不是全部筆數。算「平均每位會員消費」時，如果沒消費的會員在資料裡是 NULL，就會被排除，平均值會被高估。

## ROUND 讓數字好讀

```sql run
SELECT ROUND(AVG(total_amount))    AS aov_int,
       ROUND(AVG(total_amount), 2) AS aov_2dp
FROM orders
WHERE status = 'completed';
```

`ROUND(x)` 四捨五入到整數，`ROUND(x, 2)` 到小數第 2 位。

> [!DIALECT] AVG 整數欄位
> SQLite、MySQL、BigQuery 的 `AVG(整數欄位)` 會回傳小數。**PostgreSQL 回傳 numeric 小數也沒問題**，但 SQL Server 的 `AVG(整數)` 會回傳**整數**（捨去小數），在 SQL Server 要寫 `AVG(1.0 * x)`。
