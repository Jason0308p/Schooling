## IN：符合清單中任一個

要比對好幾個值的時候，與其寫一串 OR：

```sql
WHERE payment_method = 'line_pay' OR payment_method = 'cod' OR payment_method = 'atm'
```

不如用 `IN`：

```sql run
SELECT order_id, payment_method, total_amount
FROM orders
WHERE payment_method IN ('line_pay', 'cod', 'atm')
LIMIT 10;
```

`NOT IN (...)` 則是「都不是這些值」。

## BETWEEN：介於兩者之間（含頭尾）

```sql run
SELECT product_name, price
FROM products
WHERE price BETWEEN 300 AND 500;
```

`BETWEEN 300 AND 500` 等於 `price >= 300 AND price <= 500`，**兩端都包含**。

> [!WARN] 日期不要用 BETWEEN
> `order_date BETWEEN '2025-12-01' AND '2025-12-31'` 在欄位含時間時會漏掉 12/31 當天（12/31 15:00 比 '2025-12-31' 大）。日期一律用上一課的「`>=` 起點 `AND <` 下一期起點」。

## LIKE：模糊比對文字

| 萬用字元 | 意思 | 範例 | 會比對到 |
|---|---|---|---|
| `%` | 任意長度（含 0 個字） | `'%保溫%'` | 經典保溫杯、商務保溫瓶 |
| `_` | 剛好 1 個字 | `'A_'` | AB、A1 |

```sql run
SELECT product_name, category
FROM products
WHERE product_name LIKE '%馬克杯%';
```

- `'保溫%'`：以「保溫」**開頭**。
- `'%杯'`：以「杯」**結尾**。
- `'%保溫%'`：**包含**「保溫」。

> [!DIALECT] 大小寫
> SQLite 和 MySQL 的 `LIKE` 對英文**不分**大小寫；PostgreSQL 和 BigQuery 的 `LIKE` **區分**大小寫（PostgreSQL 不分大小寫要用 `ILIKE`，BigQuery 用 `LOWER(col) LIKE '%abc%'`）。

## NULL：「沒有資料」

NULL 代表**未知或沒填**。它不是 0，也不是空字串 `''`。

**NULL 不能用 `=` 比較**，一定要用 `IS NULL` 或 `IS NOT NULL`：

```sql run
SELECT customer_id, name, city
FROM customers
WHERE city IS NULL;
```

試試看把上面改成 `WHERE city = NULL`，會發現**一筆都沒有**。原因是任何東西跟 NULL 比較，結果都是「未知」，而 WHERE 只留下結果為「真」的列。

## NULL 最容易讓你算錯數字的地方

需求：「不住台中市的會員」。直覺寫法：

```sql
WHERE city <> '台中市'
```

這會**漏掉沒填城市的人**！因為 `NULL <> '台中市'` 的結果是「未知」，不是「真」。如果需求是「所有不是台中市的人，含沒填的」，要寫：

```sql
WHERE city <> '台中市' OR city IS NULL
```

> [!BIZ] 實務上的判斷
> 這不是語法問題，而是**需求釐清**問題：「沒填城市的人」到底要不要算？做投放名單時通常要算（他們也不是台中人），做地區分析時通常排除。遇到 NULL 時，要主動跟需求方確認。
