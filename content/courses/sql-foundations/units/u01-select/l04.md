## ORDER BY：排序

```sql run
SELECT product_name, price
FROM products
ORDER BY price DESC;
```

- `ASC`：由小到大（預設，可省略）。
- `DESC`：由大到小。

**沒寫 ORDER BY 的話，資料庫不保證任何順序。**今天看起來有排好，明天資料變多了順序就可能不同。需要順序就一定要寫。

## 多個欄位排序

先依第一個欄位排，第一個相同時再依第二個：

```sql run
SELECT name, membership_tier, signup_date
FROM customers
ORDER BY membership_tier, signup_date DESC
LIMIT 15;
```

每個欄位可以各自指定 ASC 或 DESC。

> [!TIP] 排名類需求一定要加「決勝欄位」
> 「價格最高的 5 個商品」：如果第 5 名和第 6 名一樣價錢，誰會出現是不確定的。加一個唯一的欄位當最後的排序條件（例如 `ORDER BY price DESC, product_id`），結果才會每次都一樣。這叫**確定性排序**，給主管的報表數字跑兩次不一樣，是很傷信任的事。

## LIMIT：只取前 N 筆

`LIMIT` 搭配 `ORDER BY`，就是「前幾名」：

```sql run
SELECT order_id, order_date, total_amount
FROM orders
ORDER BY total_amount DESC
LIMIT 5;
```

> [!DIALECT] 取前 N 筆的寫法
> | 資料庫 | 寫法 |
> |---|---|
> | SQLite、PostgreSQL、MySQL、BigQuery | `LIMIT 5` |
> | SQL Server | `SELECT TOP 5 ...` |
> | Oracle、標準 SQL | `FETCH FIRST 5 ROWS ONLY` |

## DISTINCT：去除重複

```sql run
SELECT DISTINCT sales_channel
FROM orders;
```

`DISTINCT` 作用在**整列**上。`SELECT DISTINCT sales_channel, status` 會回傳「通路 × 狀態」所有不重複的組合，不是兩個欄位各自去重。

> [!NOTE] NULL 在排序中的位置
> SQLite 和 MySQL 把 NULL 當作最小值（ASC 時排最前面）；PostgreSQL 和 Oracle 相反，排最後面。PostgreSQL、SQLite 3.30+ 可以寫 `ORDER BY city NULLS LAST` 明確指定。

## SQL 子句的書寫順序

到目前為止學到的子句，書寫順序是固定的：

```sql
SELECT   欄位
FROM     資料表
WHERE    篩選條件
ORDER BY 排序
LIMIT    筆數;
```

順序寫錯就會出現 syntax error。下個單元會加入 `GROUP BY` 和 `HAVING`，並解釋資料庫**實際執行**的順序，那跟書寫順序不一樣。
