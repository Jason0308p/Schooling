## WHERE：只要符合條件的列

`WHERE` 放在 `FROM` 後面，只留下符合條件的列：

```sql run
SELECT customer_id, name, membership_tier
FROM customers
WHERE membership_tier = '金卡';
```

## 比較運算子

| 運算子 | 意思 | 範例 |
|---|---|---|
| `=` | 等於 | `status = 'completed'` |
| `<>` 或 `!=` | 不等於 | `sales_channel <> 'b2b'` |
| `>` `<` | 大於、小於 | `total_amount > 1000` |
| `>=` `<=` | 大於等於、小於等於 | `price <= 500` |

- **文字要用單引號**：`'completed'`。沒加引號，資料庫會以為那是一個欄位名稱，報錯「no such column」。
- **數字不用引號**：`total_amount > 1000`。
- 等於是**一個** `=`，不是程式語言的 `==`。

## 日期的比較

這份資料的日期存成 `'2025-12-25'` 這種文字格式。因為格式固定是「年-月-日」、而且月和日都補零，**文字的大小順序剛好等於日期的先後**，所以可以直接比大小：

```sql run
SELECT order_id, order_date, total_amount
FROM orders
WHERE order_date >= '2026-06-01'
LIMIT 10;
```

> [!TIP] 日期區間用「大於等於起點、小於下一期起點」
> 要抓 2025 年 12 月整個月，最穩的寫法是：
>
> `order_date >= '2025-12-01' AND order_date < '2026-01-01'`
>
> 不要寫 `<= '2025-12-31'`。如果欄位是含時間的格式（例如 `'2025-12-31 15:30:00'`），`<= '2025-12-31'` 會漏掉最後一天的資料。左閉右開的寫法不管有沒有時間都是對的。

## AND、OR、NOT 組合條件

- `AND`：兩個條件**都要**成立。
- `OR`：**任一個**成立就好。
- `NOT`：反轉條件。

```sql run
SELECT order_id, sales_channel, total_amount
FROM orders
WHERE status = 'completed'
  AND total_amount >= 5000;
```

## 最常見的錯：AND 和 OR 混用沒加括號

需求：「已完成的訂單中，通路是官網**或** LINE 商店的」。直覺寫法：

```sql
WHERE status = 'completed'
  AND sales_channel = 'online_store'
   OR sales_channel = 'line_shop'      -- ❌ 錯
```

SQL 會**先算 AND、再算 OR**，所以上面這段實際的意思是：

> （已完成**且**官網）**或**（LINE 商店，不管有沒有完成）

連取消、退款的 LINE 訂單都會跑進來。正確寫法是**用括號把 OR 包起來**：

```sql
WHERE status = 'completed'
  AND (sales_channel = 'online_store' OR sales_channel = 'line_shop')   -- ✅ 對
```

> [!WARN] 只要同一個 WHERE 裡同時有 AND 和 OR，就一定加括號
> 就算你很確定運算順序，也請加上括號。讀你 SQL 的人不用去想優先順序，你自己也不會出錯。
