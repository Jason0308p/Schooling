## EXISTS 與 NOT EXISTS

`EXISTS` 問的是一個簡單的問題：**這個條件對應的記錄存在嗎？** 只要子查詢回傳至少一列，`EXISTS` 就是 `TRUE`——它完全不管回傳什麼值，只在乎「有沒有」。

---

## EXISTS：存在即成立

慣用寫法是 `EXISTS (SELECT 1 FROM ... WHERE ...)`。用 `SELECT 1` 而不是 `SELECT *`，明確表示「我只想知道有沒有，不在乎值」。

```sql run
-- 找出有 completed 訂單的會員
SELECT
  c.customer_id,
  c.name,
  c.membership_tier
FROM customers c
WHERE EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.customer_id
    AND o.status = 'completed'
)
ORDER BY c.membership_tier DESC, c.name
LIMIT 10;
```

> [!BIZ]
> 行銷常需要「圈出有消費過的會員」來做再行銷。`EXISTS` 讓這個意圖直接顯現在 SQL 裡：「找出這樣的會員——他們的訂單記錄中存在 completed 的」。

---

## NOT EXISTS：找出缺漏

`NOT EXISTS` 是找「另一張表**沒有**對應記錄」的標準寫法，非常適合找「從未……」類型的問題。

```sql run
-- 找出「從未購買」的會員（從未有 completed 訂單）
SELECT
  customer_id,
  name,
  signup_date,
  acquisition_channel
FROM customers c
WHERE NOT EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.customer_id
    AND o.status = 'completed'
)
ORDER BY signup_date DESC
LIMIT 10;
```

> [!TIP]
> 「從未購買的會員」是喚回行銷的核心名單。`NOT EXISTS` 的語義非常直白：「找出這樣的會員——不存在任何屬於他們的 completed 訂單」。這比用 LEFT JOIN + IS NULL 更容易一眼看懂目的。

---

## EXISTS 跨多張表

`EXISTS` 的子查詢可以 JOIN 多張表，只要最後的 WHERE 條件能正確關聯到外層即可。

```sql run
-- 找出「在廣告活動期間，有對應 session 且該 session 有 purchase 事件」的活動
SELECT
  campaign_id,
  campaign_name,
  platform,
  start_date,
  end_date
FROM campaigns c
WHERE EXISTS (
  SELECT 1
  FROM sessions s
  JOIN events e ON s.session_id = e.session_id
  WHERE s.campaign_id = c.campaign_id
    AND e.event_name = 'purchase'
)
ORDER BY start_date;
```

> [!WARN]
> EXISTS 子查詢裡的 WHERE 條件必須包含**與外層表的關聯條件**（這裡是 `s.campaign_id = c.campaign_id`），否則子查詢變成無相關子查詢，每一列都回傳同樣結果，邏輯就錯了。

---

## IN vs EXISTS：選哪個？

兩者很多時候可以互換，但有細微差別：

| 比較點 | IN | EXISTS |
|--------|-----|--------|
| 子查詢 NULL 處理 | `IN (NULL, ...)` 不會匹配任何值 | EXISTS 不受 NULL 影響 |
| 語義清晰度 | 適合「從清單中比對」 | 適合「確認對應記錄存在」 |
| 子查詢很大時 | 可能較慢（需建立清單）| 找到第一筆就停止，通常較快 |

> [!DIALECT]
> **EXISTS 行為**：三種資料庫（SQLite / PostgreSQL / BigQuery）的 EXISTS 語義完全相同。
>
> **NOT IN vs NOT EXISTS 的 NULL 陷阱**：如果子查詢結果中有 NULL，`NOT IN` 整個條件會變成 `UNKNOWN`（等同 FALSE），導致外層查詢回傳空結果。`NOT EXISTS` 則不受影響。**建議統一用 NOT EXISTS 取代 NOT IN**，避免這個地雷。
>
> **效能**：PostgreSQL 和 BigQuery 的查詢優化器通常能把 EXISTS 和 JOIN 轉換成同樣的執行計畫；SQLite 較簡單，EXISTS 通常略優於大清單的 IN。
