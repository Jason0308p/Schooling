## WITH（CTE）基礎

CTE（Common Table Expression，公用資料表運算式）用 `WITH` 關鍵字定義，讓你在查詢開頭先「命名一個子查詢」，後面再用名字引用它。

---

## 基本語法

```sql
WITH cte_name AS (
  SELECT ...
)
SELECT ...
FROM cte_name
WHERE ...;
```

就這樣。`WITH` 定義的 CTE 只在這次查詢中有效，查詢結束就消失——不是真的建立一張表，只是讓這次查詢更好讀。

---

## 為什麼要用 CTE？

把 L01 的 FROM 子查詢和 CTE 版本並排：

**子查詢版（難以閱讀）**
```sql
SELECT month, monthly_revenue
FROM (
  SELECT strftime('%Y-%m', order_date) AS month, SUM(total_amount) AS monthly_revenue
  FROM orders WHERE status = 'completed' GROUP BY month
) AS t
WHERE monthly_revenue > (SELECT AVG(monthly_revenue) FROM (
  SELECT strftime('%Y-%m', order_date) AS month, SUM(total_amount) AS monthly_revenue
  FROM orders WHERE status = 'completed' GROUP BY month
));
```

**CTE 版（清晰易讀）**
```sql
WITH monthly_revenue AS (
  SELECT strftime('%Y-%m', order_date) AS month, SUM(total_amount) AS monthly_revenue
  FROM orders WHERE status = 'completed' GROUP BY month
)
SELECT month, monthly_revenue
FROM monthly_revenue
WHERE monthly_revenue > (SELECT AVG(monthly_revenue) FROM monthly_revenue);
```

同樣的邏輯，CTE 版不僅更短，還讓你能看出「我在做什麼」。

---

## 範例 1：用 CTE 計算訂單數，再找高於門檻的會員

```sql run
-- 先用 CTE 算每位會員的 completed 訂單數，再找訂單數 > 3 的
WITH customer_order_counts AS (
  SELECT
    customer_id,
    COUNT(*) AS order_count
  FROM orders
  WHERE status = 'completed'
  GROUP BY customer_id
)
SELECT
  c.customer_id,
  c.name,
  c.membership_tier,
  coc.order_count
FROM customers c
JOIN customer_order_counts coc ON c.customer_id = coc.customer_id
WHERE coc.order_count > 3
ORDER BY coc.order_count DESC;
```

> [!BIZ]
> 訂單數高的會員是最忠實的客戶，值得優先給予升等邀請或獨家優惠。CTE 讓「先算訂單數、再篩選」的兩步邏輯清楚分開，同事一看就懂在做什麼。

## 範例 2：用 CTE 算月營收

```sql run
-- 用 CTE 計算各月營收（這是之後做趨勢分析的基礎）
WITH monthly_revenue AS (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    COUNT(DISTINCT order_id)      AS order_count,
    ROUND(SUM(total_amount), 0)   AS revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
)
SELECT
  month,
  order_count,
  revenue
FROM monthly_revenue
ORDER BY month;
```

> [!TIP]
> 用 CTE 把「月營收的計算邏輯」封裝起來，後面不管是要算環比成長、找異常月份、還是加上同期比較，都只需要在外層加工，不必每次重寫 GROUP BY 的計算。

## 範例 3：把 IN 子查詢改寫成 CTE + JOIN

```sql run
-- 購買過保溫杯的會員（CTE 版，比 IN 子查詢更靈活）
WITH thermos_buyers AS (
  SELECT DISTINCT o.customer_id
  FROM orders o
  JOIN order_items oi ON o.order_id = oi.order_id
  JOIN products p     ON oi.product_id = p.product_id
  WHERE p.category = '保溫杯'
    AND o.status = 'completed'
)
SELECT
  c.customer_id,
  c.name,
  c.membership_tier,
  c.city
FROM customers c
JOIN thermos_buyers tb ON c.customer_id = tb.customer_id
ORDER BY c.membership_tier DESC, c.name
LIMIT 10;
```

> [!TIP]
> CTE 版的另一個好處：如果你後來想在 `thermos_buyers` 裡加更多條件（例如只算今年），只需要改 CTE 內部，外層查詢完全不用動。子查詢版則需要到巢狀結構裡面找。

## CTE 的限制

- CTE **只在當次查詢有效**，下一個 `SELECT` 就消失了
- SQLite、PostgreSQL、BigQuery 都支援 CTE，語法完全相同
- CTE 不一定比子查詢快——資料庫可能以相同方式執行；CTE 的價值主要在**可讀性**

> [!DIALECT]
> **CTE 支援度**
> - **SQLite**：3.8.3+ 支援 CTE（含遞迴 CTE）
> - **PostgreSQL**：完整支援，預設 CTE 是「優化屏障」（optimization fence），加 `NOT MATERIALIZED` 可讓優化器穿透
> - **BigQuery**：完整支援，CTE 會被優化器內聯展開
>
> **遞迴 CTE**（`WITH RECURSIVE`）三種資料庫都支援，用於處理樹狀/階層資料，本課暫不涵蓋。
