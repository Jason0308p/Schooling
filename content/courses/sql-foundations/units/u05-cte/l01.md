## WHERE 子查詢與 FROM 子查詢

子查詢（Subquery）就是「查詢裡面再放一個查詢」。外層查詢會把內層查詢的結果當成資料來用——可以當篩選條件、當一張暫時的表，甚至當一個單一值。

---

## 三種常見用法

### 1. Scalar 子查詢：回傳一個值

放在 `WHERE x = (...)` 或 `WHERE x > (...)` 的位置，子查詢必須只回傳**一列一欄**。

```sql run
-- 找出 total_amount 高於所有 completed 訂單平均值的訂單
SELECT
  order_id,
  customer_id,
  order_date,
  total_amount
FROM orders
WHERE status = 'completed'
  AND total_amount > (
    SELECT AVG(total_amount)
    FROM orders
    WHERE status = 'completed'
  )
ORDER BY total_amount DESC
LIMIT 10;
```

> [!BIZ]
> 這是最常見的業務問題：「找出高於平均的那些」。先讓資料庫算出平均值，再拿這個值當門檻篩選——子查詢讓這件事一行搞定，不需要把平均值先記下來。

---

### 2. IN 子查詢：回傳一欄多列

放在 `WHERE x IN (SELECT ...)` 的位置，子查詢回傳一欄，外層拿這欄做清單比對。

```sql run
-- 找出購買過「保溫杯」類別商品的會員（IN 子查詢）
SELECT
  customer_id,
  name,
  membership_tier
FROM customers
WHERE customer_id IN (
  SELECT DISTINCT o.customer_id
  FROM orders o
  JOIN order_items oi ON o.order_id = oi.order_id
  JOIN products p ON oi.product_id = p.product_id
  WHERE p.category = '保溫杯'
    AND o.status = 'completed'
)
ORDER BY membership_tier, name;
```

> [!TIP]
> 子查詢裡加 `DISTINCT` 可以去重，讓外層的 `IN` 清單乾淨——雖然效能差異不大，但讓意圖更清楚：「我只需要知道這個人有沒有買過」。

---

### 3. FROM 子查詢（衍生表）：把查詢結果當成一張表

把 `SELECT` 放在 `FROM` 後面，加上別名，就像自己建了一張暫時的表。

```sql run
-- 先用子查詢算出各月營收，再找高於月平均的月份
SELECT
  month,
  monthly_revenue
FROM (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    SUM(total_amount)             AS monthly_revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
) AS monthly_stats
WHERE monthly_revenue > (
  SELECT AVG(monthly_revenue)
  FROM (
    SELECT
      strftime('%Y-%m', order_date) AS month,
      SUM(total_amount)             AS monthly_revenue
    FROM orders
    WHERE status = 'completed'
    GROUP BY month
  )
)
ORDER BY month;
```

> [!WARN]
> FROM 後面的子查詢**一定要有別名**（如 `AS monthly_stats`），否則 SQLite 會報錯。這個別名就是這張「臨時表」的名字，外層 SELECT 可以用它存取欄位。

---

## 執行順序：內層先跑，外層再用

```
外層 SQL 看到子查詢
  → 資料庫先執行內層子查詢，得到結果
  → 把結果交給外層 SQL 使用
  → 外層 SQL 繼續執行
```

這就像你跟同事說「把銷售前 10 名的客戶列出來，我再從中找金卡會員」——你的同事先查前 10 名，你再過濾，兩個步驟依序完成。

---

## 子查詢 vs JOIN：什麼時候用哪個？

| 情境 | 建議 |
|------|------|
| 只需要從另一張表做篩選，不需要那張表的欄位 | 子查詢（意圖更清楚） |
| 需要同時顯示多張表的欄位 | JOIN |
| 需要的邏輯是「有沒有對應記錄」 | EXISTS（L02 會介紹）|
| 子查詢結果需要被多次使用 | CTE（L03 會介紹）|

> [!DIALECT]
> **月份格式化**
> - **SQLite**：`strftime('%Y-%m', order_date)`
> - **PostgreSQL**：`TO_CHAR(order_date, 'YYYY-MM')` 或 `DATE_TRUNC('month', order_date)`
> - **BigQuery**：`FORMAT_DATE('%Y-%m', order_date)` 或 `DATE_TRUNC(order_date, MONTH)`
>
> **衍生表別名**：三種資料庫都必須有別名，BigQuery 不需要 `AS` 關鍵字但建議加上。
