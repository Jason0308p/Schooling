# L03：哪些會員值得做再行銷？

> 再行銷的黃金原則：找對人比找多人更重要。沉睡但曾消費過的顧客，比從未買過的訪客便宜 5 倍以上。

---

## 主管需求

> 「我要做一個 Facebook 再行銷名單：30 天內沒有訂單但過去曾買過的會員，給我 email 名單。」

這個需求包含兩個條件：

1. **「曾買過」**：有至少一筆 `completed` 訂單（不計 refunded/cancelled）
2. **「近 30 天沒買」**：在分析截止日（`2026-06-30`）前 29 天內無 completed 訂單

---

## 分析思路

```
所有有 completed 訂單的會員
  → 排除近 30 天有訂單的
  → 加上 email
  → 匯出
```

「排除」的寫法有兩種：`NOT EXISTS` 和 `LEFT JOIN ... WHERE IS NULL`，兩者效果相同，`NOT EXISTS` 語意更清楚。

---

## 步驟一：定義基準日期

```sql run
SELECT
  date('2026-06-30', '-29 days') AS cutoff_30d,
  date('2026-06-30', '-89 days') AS cutoff_90d;
```

| cutoff_30d | cutoff_90d |
|------------|------------|
| 2026-06-01 | 2026-04-02 |

> [!BIZ]
> 「近 30 天」的定義決定名單大小。`-29 days` 表示從今天往回算包含今天共 30 天。業務上要跟需求方確認「含當天嗎？」這類邊界問題。

---

## 步驟二：用 NOT EXISTS 排除近期購買者

```sql run
SELECT
  c.customer_id,
  c.name,
  c.email,
  MAX(o.order_date)           AS last_order_date,
  ROUND(SUM(o.total_amount))  AS total_spent
FROM customers c
JOIN orders o
  ON o.customer_id = c.customer_id
 AND o.status = 'completed'
WHERE NOT EXISTS (
  SELECT 1
  FROM orders recent
  WHERE recent.customer_id = c.customer_id
    AND recent.status = 'completed'
    AND recent.order_date >= date('2026-06-30', '-29 days')
)
GROUP BY c.customer_id, c.name, c.email
ORDER BY total_spent DESC
LIMIT 20;
```

> [!BIZ]
> `NOT EXISTS` 內層的 subquery 只需要找到一筆近期訂單就會讓外層排除這個顧客。比起 `NOT IN`，`NOT EXISTS` 在 NULL 值存在時更安全，且通常效能更好。

---

## 步驟三：進階分層——「活躍但剛沉睡」

高價值再行銷：90 天內有買、但 30 天內沒買。這批人剛剛流失，喚回成本最低：

```sql run
SELECT
  c.customer_id,
  c.name,
  c.email,
  MAX(o.order_date) AS last_order_date
FROM customers c
JOIN orders o
  ON o.customer_id = c.customer_id
 AND o.status = 'completed'
 AND o.order_date >= date('2026-06-30', '-89 days')
WHERE NOT EXISTS (
  SELECT 1
  FROM orders recent
  WHERE recent.customer_id = c.customer_id
    AND recent.status = 'completed'
    AND recent.order_date >= date('2026-06-30', '-29 days')
)
GROUP BY c.customer_id, c.name, c.email
ORDER BY last_order_date DESC
LIMIT 20;
```

---

## 不同再行銷策略對應的 SQL 邏輯

| 策略 | 條件 | 預期效果 |
|------|------|---------|
| 喚回剛沉睡 | 90天內買過，近30天無訂單 | 回購率最高 |
| 喚回深度沉睡 | 180天以上未購，但總消費高 | 需要更強誘因 |
| 升等推送 | 銀卡會員但總消費接近金卡門檻 | 提升 LTV |

---

## 小結

| 工具 | 用途 |
|------|------|
| `NOT EXISTS` | 排除有近期訂單的顧客，語意清晰 |
| `date('2026-06-30', '-29 days')` | SQLite 日期運算 |
| `MAX(order_date)` | 取最後購買日 |
| 分層邏輯 | 「剛沉睡」比「全沉睡」名單質量更高 |
