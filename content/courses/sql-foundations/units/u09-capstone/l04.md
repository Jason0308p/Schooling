# L04：數字對不起來怎麼辦？

> 兩套系統的數字永遠不會完全一致。你的工作是找出差異的模式，而不是消除所有差異。

---

## 主管需求

> 「我看 GA4 報表和後台訂單數對不起來，你去查一下哪裡有差異。」

這是數據分析師最常遇到的問題，也是最需要冷靜處理的情況。

---

## 為什麼兩邊會不一樣？

| 原因 | GA4 端（sessions/events） | 後台端（orders） |
|------|--------------------------|-----------------|
| 廣告遮蔽器 | 部分用戶的 purchase 事件沒觸發 | 訂單照常成立 |
| 多裝置 | 同一人在手機點廣告、桌機下單 | 訂單只有一筆 |
| 退款 | GA4 不追蹤 refund 事件 | orders 有 refunded |
| 延遲到達 | 事件可能晚幾小時才進資料庫 | 訂單即時寫入 |
| 重複 session | 重新整理頁面產生多個 session | 訂單不重複 |

---

## 步驟一：先對齊粒度——每日比較

```sql run
WITH daily_events AS (
  SELECT
    DATE(e.event_time) AS date_key,
    COUNT(*)           AS event_purchases
  FROM events e
  WHERE e.event_name = 'purchase'
  GROUP BY DATE(e.event_time)
),
daily_orders AS (
  SELECT
    order_date         AS date_key,
    COUNT(*)           AS order_completions
  FROM orders
  WHERE status = 'completed'
  GROUP BY order_date
)
SELECT
  COALESCE(de.date_key, do.date_key)  AS date_key,
  COALESCE(de.event_purchases, 0)     AS event_purchases,
  COALESCE(do.order_completions, 0)   AS order_completions,
  COALESCE(do.order_completions, 0)
    - COALESCE(de.event_purchases, 0) AS diff
FROM daily_events  de
FULL OUTER JOIN daily_orders do
  ON de.date_key = do.date_key
ORDER BY ABS(diff) DESC
LIMIT 10;
```

> [!BIZ]
> SQLite 不支援 `FULL OUTER JOIN`，改用兩個 CTE 再 LEFT JOIN 兩次，或用 UNION 合併日期清單。上面的寫法在 PostgreSQL/BigQuery 可直接執行；SQLite 版本見下面的步驟二。

---

## 步驟二：SQLite 相容版（UNION 日期清單）

```sql run
WITH all_dates AS (
  SELECT DATE(event_time) AS date_key FROM events WHERE event_name = 'purchase'
  UNION
  SELECT order_date       AS date_key FROM orders WHERE status = 'completed'
),
daily_events AS (
  SELECT DATE(event_time) AS date_key, COUNT(*) AS event_purchases
  FROM events WHERE event_name = 'purchase'
  GROUP BY DATE(event_time)
),
daily_orders AS (
  SELECT order_date AS date_key, COUNT(*) AS order_completions
  FROM orders WHERE status = 'completed'
  GROUP BY order_date
)
SELECT
  ad.date_key,
  COALESCE(de.event_purchases,  0) AS event_purchases,
  COALESCE(do.order_completions,0) AS order_completions,
  COALESCE(do.order_completions,0)
    - COALESCE(de.event_purchases, 0) AS diff
FROM all_dates ad
LEFT JOIN daily_events de ON de.date_key = ad.date_key
LEFT JOIN daily_orders do ON do.date_key = ad.date_key
ORDER BY ABS(diff) DESC
LIMIT 10;
```

> [!BIZ]
> `UNION`（去重）合併兩張表的日期，確保即使某天只有 events 或只有 orders，也不會被漏掉。`COALESCE(..., 0)` 把 NULL 轉成 0，讓差值計算有意義。

## 步驟三：鎖定有問題的 session

找出「events 有 purchase，但 session 對應的顧客當天沒有 completed 訂單」的可疑 session：

```sql run
SELECT
  s.session_id,
  s.customer_id,
  DATE(e.event_time) AS event_date
FROM events e
JOIN sessions s ON s.session_id = e.session_id
WHERE e.event_name = 'purchase'
  AND s.customer_id IS NOT NULL
  AND NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = s.customer_id
      AND o.status      = 'completed'
      AND o.order_date  = DATE(e.event_time)
  )
ORDER BY event_date ASC
LIMIT 20;
```

> [!BIZ]
> `customer_id IS NOT NULL` 是必要條件，匿名 session 無法追蹤到訂單，屬於預期行為。這份清單是「有登入卻沒訂單」的異常 session，可以進一步查是放棄結帳還是資料遺漏。

---

## 怎麼跟主管報告

不要說「因為兩邊計算方式不同所以一定會不一樣」（廢話）。要說：

> 「2025 年 11 月 11 日前後有 3 天差異超過 15 筆，events purchase 事件明顯多於後台 completed 訂單。推測是雙 11 當天高流量造成部分結帳流程未完成（session 觸發了 purchase 事件但訂單未成立），建議工程師確認結帳 API 當天的錯誤日誌。」

---

## 小結

| 工具 | 用途 |
|------|------|
| UNION 日期清單 | SQLite 中模擬 FULL OUTER JOIN |
| `COALESCE(..., 0)` | 把缺漏的 NULL 轉成 0 |
| `NOT EXISTS` | 找「有 A 但沒有對應 B」的記錄 |
| `ABS(diff) DESC` | 把差異最大的日期排前面 |
