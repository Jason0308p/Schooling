# L02：雙 11 活動成效檢討

> 廣告成效不只看花了多少，更要看帶回多少。ROAS 是最簡單的對話語言。

---

## 主管需求

> 「11 月的廣告活動花了多少、帶來多少訂單？ROAS 夠嗎？」

行銷主管的口頭禪是 ROAS（Return on Ad Spend）：

```
ROAS = 廣告帶來的訂單營收 ÷ 廣告花費
```

ROAS > 1 代表每花 1 元廣告費，至少帶回 1 元營收。電商通常要求 ROAS ≥ 3 才算健康。

---

## 分析思路

```
廣告花費（ad_spend）
        ↓
  campaign 層級彙總
        ↓
透過 sessions.campaign_id 串聯 orders
        ↓
計算 attributed revenue → ROAS
```

注意：`sessions` 是入口，`orders` 是結果。一個 session 可能對應到後來下單的 customer，但只有 `sessions.customer_id` 不為 NULL 才能串到 orders。

---

## 步驟一：看 11 月廣告總花費

```sql run
SELECT
  c.campaign_id,
  c.campaign_name,
  c.platform,
  ROUND(SUM(a.cost))        AS total_cost,
  SUM(a.conversions)        AS total_conversions
FROM campaigns c
JOIN ad_spend a ON c.campaign_id = a.campaign_id
WHERE a.spend_date >= '2025-11-01'
  AND a.spend_date <  '2025-12-01'
GROUP BY c.campaign_id, c.campaign_name, c.platform
ORDER BY total_cost DESC;
```

> [!BIZ]
> `conversions` 是廣告平台自己認定的轉換數，通常比實際訂單數樂觀（因為歸因窗口不同）。後面要用自己的訂單資料交叉驗證。

---

## 步驟二：透過 sessions 追蹤訂單

```sql run
SELECT
  c.campaign_name,
  c.platform,
  COUNT(DISTINCT o.order_id)  AS attributed_orders,
  ROUND(SUM(o.total_amount))  AS attributed_revenue
FROM campaigns c
JOIN sessions  s ON s.campaign_id = c.campaign_id
JOIN orders    o ON o.customer_id = s.customer_id
WHERE s.session_start >= '2025-11-01'
  AND s.session_start <  '2025-12-01'
  AND o.order_date    >= '2025-11-01'
  AND o.order_date    <  '2025-12-01'
  AND o.status = 'completed'
  AND s.campaign_id IS NOT NULL
GROUP BY c.campaign_name, c.platform
ORDER BY attributed_revenue DESC;
```

> [!BIZ]
> 這裡的歸因是「同月內有該廣告 session 的顧客，同月的 completed 訂單」。這是簡化的 last-touch 歸因，不代表廣告直接促成購買，但在沒有完整歸因系統的情況下是合理的起點。

---

## 步驟三：合併計算 ROAS

```sql run
WITH spend AS (
  SELECT
    c.campaign_id,
    c.campaign_name,
    c.platform,
    ROUND(SUM(a.cost)) AS total_cost
  FROM campaigns c
  JOIN ad_spend a ON c.campaign_id = a.campaign_id
  WHERE a.spend_date >= '2025-11-01'
    AND a.spend_date <  '2025-12-01'
  GROUP BY c.campaign_id, c.campaign_name, c.platform
),
attributed AS (
  SELECT
    c.campaign_id,
    ROUND(SUM(o.total_amount)) AS attributed_revenue
  FROM campaigns c
  JOIN sessions  s ON s.campaign_id = c.campaign_id
  JOIN orders    o ON o.customer_id = s.customer_id
  WHERE s.session_start >= '2025-11-01'
    AND s.session_start <  '2025-12-01'
    AND o.order_date    >= '2025-11-01'
    AND o.order_date    <  '2025-12-01'
    AND o.status = 'completed'
    AND s.campaign_id IS NOT NULL
  GROUP BY c.campaign_id
)
SELECT
  sp.campaign_name,
  sp.platform,
  sp.total_cost,
  at.attributed_revenue,
  ROUND(at.attributed_revenue * 1.0 / NULLIF(sp.total_cost, 0), 2) AS roas
FROM spend sp
LEFT JOIN attributed at ON sp.campaign_id = at.campaign_id
ORDER BY roas DESC NULLS LAST;
```

> [!BIZ]
> `NULLIF(total_cost, 0)` 避免除以零。`LEFT JOIN` 確保即使某活動沒有追蹤到訂單，也會出現在結果（ROAS 為 NULL）。ROAS NULL 比 ROAS 0 更誠實：代表「無法歸因」而非「完全沒效果」。

---

## 小結

| 概念 | 說明 |
|------|------|
| ROAS | 廣告帶回的營收 ÷ 廣告花費 |
| 歸因窗口 | 這裡用「同月有 session → 同月訂單」的簡化邏輯 |
| `NULLIF` | 防除以零的安全寫法 |
| `LEFT JOIN` + `NULLS LAST` | 讓無效活動也出現，且排在最後 |
