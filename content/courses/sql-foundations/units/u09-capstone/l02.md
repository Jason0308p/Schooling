# L02：雙 11 活動成效檢討

> 廣告成效不只看花了多少，更要看帶回多少。ROAS 是最簡單的對話語言。

---

## 主管需求

> 「11 月的廣告活動花了多少、帶來多少訂單？ROAS 夠嗎？」

行銷主管的口頭禪是 ROAS（Return on Ad Spend）：

```
ROAS = 廣告帶來的訂單營收 ÷ 廣告花費
```

ROAS > 1 代表每花 1 元廣告費，至少帶回 1 元營收。電商通常要求 ROAS ≥ 3 才算健康。

---

## 分析思路

```
廣告花費（ad_spend）
        ↓
  campaign 層級彙總
        ↓
透過 sessions.campaign_id 串聯 orders
        ↓
計算 attributed revenue → ROAS
```

注意：`sessions` 是入口，`orders` 是結果。一個 session 可能對應到後來下單的 customer，但只有 `sessions.customer_id` 不為 NULL 才能串到 orders。

---

## 步驟一：看 11 月廣告總花費

```sql run
SELECT
  c.campaign_id,
  c.campaign_name,
  c.platform,
  ROUND(SUM(a.cost))        AS total_cost,
  SUM(a.conversions)        AS total_conversions
FROM campaigns c
JOIN ad_spend a ON c.campaign_id = a.campaign_id
WHERE a.spend_date >= '2025-11-01'
  AND a.spend_date <  '2025-12-01'
GROUP BY c.campaign_id, c.campaign_name, c.platform
ORDER BY total_cost DESC;
```

> [!BIZ]
> `conversions` 是廣告平台自己認定的轉換數，通常比實際訂單數樂觀（因為歸因窗口不同）。後面要用自己的訂單資料交叉驗證。

---

## 步驟二：透過 sessions 追蹤訂單

```sql run
WITH ranked_touches AS (
  SELECT o.order_id, o.total_amount, s.campaign_id,
    ROW_NUMBER() OVER (
      PARTITION BY o.order_id
      ORDER BY s.session_start DESC, s.session_id DESC
    ) AS touch_rank
  FROM orders o
  JOIN sessions s ON s.customer_id = o.customer_id
    AND DATE(s.session_start) >= DATE(o.order_date, '-30 days')
    AND DATE(s.session_start) < DATE(o.order_date)
  WHERE o.status = 'completed' AND s.campaign_id IS NOT NULL
    AND o.order_date >= '2025-11-01' AND o.order_date < '2025-12-01'
),
winners AS (
  SELECT order_id, total_amount, campaign_id
  FROM ranked_touches WHERE touch_rank = 1
)
SELECT campaign_id, COUNT(*) AS attributed_orders,
  ROUND(SUM(total_amount)) AS attributed_revenue
FROM winners
GROUP BY campaign_id
ORDER BY attributed_revenue DESC, campaign_id ASC;
```

> [!BIZ]
> 本課自訂教學模型（不是 GA4 Last Click）：同會員的 completed 訂單，候選 session 必須 campaign_id 非 NULL，日期在訂單日前 30 個完整日（含第 30 日、不含訂單同日）。選 session_start 最大者，同時刻以 session_id DESC 決勝。每單只歸屬一個活動，無候選不歸因。報表以 11 月訂單及花費為準；回溯 session 可在 10 月。先每單唯一再 SUM，不能 SUM(DISTINCT 金額)，也不是因果結論。

---

## 步驟三：合併計算 ROAS

```sql run
WITH ranked_touches AS (
  SELECT o.order_id, o.total_amount, s.campaign_id,
    ROW_NUMBER() OVER (
      PARTITION BY o.order_id
      ORDER BY s.session_start DESC, s.session_id DESC
    ) AS touch_rank
  FROM orders o
  JOIN sessions s ON s.customer_id = o.customer_id
    AND DATE(s.session_start) >= DATE(o.order_date, '-30 days')
    AND DATE(s.session_start) < DATE(o.order_date)
  WHERE o.status = 'completed' AND s.campaign_id IS NOT NULL
    AND o.order_date >= '2025-11-01' AND o.order_date < '2025-12-01'
),
winners AS (
  SELECT order_id, total_amount, campaign_id
  FROM ranked_touches WHERE touch_rank = 1
),
spend AS (
  SELECT c.campaign_id, c.campaign_name, c.platform,
    ROUND(SUM(a.cost)) AS total_cost
  FROM campaigns c JOIN ad_spend a ON a.campaign_id = c.campaign_id
  WHERE a.spend_date >= '2025-11-01' AND a.spend_date < '2025-12-01'
  GROUP BY c.campaign_id, c.campaign_name, c.platform
),
revenue AS (
  SELECT campaign_id, ROUND(SUM(total_amount)) AS attributed_revenue
  FROM winners GROUP BY campaign_id
)
SELECT sp.campaign_name, sp.platform, sp.total_cost,
  rv.attributed_revenue AS attributed_revenue,
  ROUND(rv.attributed_revenue * 1.0 / NULLIF(sp.total_cost, 0), 2) AS roas
FROM spend sp LEFT JOIN revenue rv ON rv.campaign_id = sp.campaign_id
ORDER BY roas DESC NULLS LAST, sp.campaign_id ASC;
```

> [!BIZ]
> `NULLIF(total_cost, 0)` 避免除以零。`LEFT JOIN` 確保即使某活動沒有追蹤到訂單，也會出現在結果（ROAS 為 NULL）。ROAS NULL 比 ROAS 0 更誠實：代表「無法歸因」而非「完全沒效果」。

---

## 小結

| 概念 | 說明 |
|------|------|
| ROAS | 廣告帶回的營收 ÷ 廣告花費 |
| 歸因窗口 | 訂單前 30 完整日，最後有效 session；同時刻 session_id DESC 決勝 |
| `NULLIF` | 防除以零的安全寫法 |
| `LEFT JOIN` + `NULLS LAST` | 讓無效活動也出現，且排在最後 |
