# 累計與移動平均

聚合函數加上 `OVER (ORDER BY ...)` 就能計算**累計值**；再加上 `ROWS BETWEEN` 框架，就能計算**移動平均**。這是分析趨勢、平滑雜訊的核心工具。

> [!BIZ]
> 月營收折線圖旁邊加一條「累計營收」，可以直觀看到年度目標完成進度。廣告每日花費波動大，加上 7 日移動平均線，可以過濾週期性雜訊、看清趨勢。

---

## 累計加總：SUM OVER (ORDER BY ...)

```sql
SUM(欄位) OVER (ORDER BY 日期欄)
```

加上 `ORDER BY` 後，`SUM` 預設使用 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`——即從第一列累加到當前列。

---

## 範例 1：月累計營收

```sql run
WITH monthly AS (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    ROUND(SUM(total_amount), 0)   AS monthly_revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
)
SELECT
  month,
  monthly_revenue,
  SUM(monthly_revenue) OVER (ORDER BY month) AS cumulative_revenue
FROM monthly
ORDER BY month;
```

> [!TIP]
> `SUM ... OVER (ORDER BY month)` 不加 `PARTITION BY`，代表累計是跨整個資料期間的全域累計。若要按年度重置，加上 `PARTITION BY strftime('%Y', month || '-01')`。

---

## 範例 2：7 筆移動平均（ROWS BETWEEN）

```sql run
WITH daily_revenue AS (
  SELECT
    order_date,
    ROUND(SUM(total_amount), 0) AS daily_revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY order_date
)
SELECT
  order_date,
  daily_revenue,
  ROUND(
    AVG(daily_revenue) OVER (
      ORDER BY order_date
      ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ),
    0
  ) AS ma7
FROM daily_revenue
ORDER BY order_date;
```

> [!WARN]
> **ROWS vs RANGE**：
> - `ROWS BETWEEN`：精確按物理列數計算，永遠取前 6 列 + 當前列，最多 7 列
> - `RANGE BETWEEN`：按值範圍計算，若有重複值（同一天多列），行為不同
>
> `ROWS` 表示最近幾筆，不保證最近幾天；缺日要先補日期表，或用數值日期鍵搭配 RANGE。

## 範例 3：每筆訂單佔累計營收的比例

```sql run
WITH ordered AS (
  SELECT
    order_id,
    order_date,
    customer_id,
    total_amount,
    SUM(total_amount) OVER (ORDER BY order_date, order_id) AS running_total
  FROM orders
  WHERE status = 'completed'
)
SELECT
  order_id,
  order_date,
  total_amount,
  ROUND(running_total, 0)                           AS running_total,
  ROUND(total_amount * 100.0 / NULLIF(running_total, 0), 2)    AS pct_of_running
FROM ordered
ORDER BY order_date, order_id
LIMIT 20;
```

> [!BIZ]
> 這是「本筆金額 / 截至本筆的累計金額」，不是帕累托的累計貢獻率。先乘 `100.0` 避免整數除法，累計為 0 時回傳 NULL。帕累托分析需先按客戶或商品彙總、按貢獻降冪排序，再算「累計金額 / 全體總金額」。

## ROWS BETWEEN 框架語法總覽

```sql
ROWS BETWEEN <起點> AND <終點>
```

| 關鍵字 | 意義 |
|--------|------|
| `UNBOUNDED PRECEDING` | 從第一列開始 |
| `N PRECEDING` | 當前列往前 N 列 |
| `CURRENT ROW` | 當前列 |
| `N FOLLOWING` | 當前列往後 N 列 |
| `UNBOUNDED FOLLOWING` | 到最後一列結束 |

常見組合：
- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`：逐列累計（須明寫；預設為 RANGE）
- `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`：7 期移動平均
- `ROWS BETWEEN 3 PRECEDING AND 3 FOLLOWING`：置中移動平均（前後各 3 期）

## COUNT OVER：累計筆數

```sql run
WITH monthly AS (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    COUNT(*)                      AS order_count
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
)
SELECT
  month,
  order_count,
  SUM(order_count) OVER (ORDER BY month) AS cumulative_orders
FROM monthly
ORDER BY month;
```

> [!DIALECT]
> **SQLite**：`ROWS BETWEEN` 和 `RANGE BETWEEN` 自 3.25 起支援視窗函數；`RANGE` 的數值偏移邊界與 `GROUPS` 自 3.28.0 起支援，參見官方 release notes（https://www.sqlite.org/releaselog/3_28_0.html）。
> **PostgreSQL**：另支援 `GROUPS BETWEEN`（按 ORDER BY 同值的 peer group 計算，11+），參見官方 PostgreSQL 11 release notes（https://www.postgresql.org/docs/11/release-11.html）。
> **BigQuery**：`RANGE` 要求 ORDER BY 只有一個數值運算式；日期可寫 `ORDER BY UNIX_DATE(date_col) RANGE BETWEEN 6 PRECEDING AND CURRENT ROW`。時間戳可轉 UNIX_SECONDS 等數值，參見官方 window function calls（https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/window-function-calls）。
