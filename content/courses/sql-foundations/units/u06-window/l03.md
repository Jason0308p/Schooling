# LAG 和 LEAD：前後期比較

`LAG` 和 `LEAD` 讓你在同一列裡取得「前幾列」或「後幾列」的值，不需要自我 JOIN。最典型的應用是**環比計算**和**購買間隔分析**。

> [!BIZ]
> 「本月營收比上月成長多少？」、「這位客戶上次購買是幾天前？」——這類前後期比較問題用傳統 JOIN 寫起來繁瑣，用 `LAG`/`LEAD` 只需幾行。

---

## 語法

```sql
LAG(欄位, 偏移量, 預設值)  OVER (PARTITION BY ... ORDER BY ...)
LEAD(欄位, 偏移量, 預設值) OVER (PARTITION BY ... ORDER BY ...)
```

- **偏移量**（offset）：預設為 1，取前/後第 1 列
- **預設值**（default）：當前/後列不存在時回傳此值（預設為 NULL）
- `ORDER BY` 決定「前後」的順序

---

## 範例 1：月營收趨勢 + LAG 取上月營收

先用 CTE 彙總月營收，再用 LAG 取上月：

```sql run
WITH monthly AS (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    ROUND(SUM(total_amount), 0)   AS revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
)
SELECT
  month,
  revenue,
  LAG(revenue) OVER (ORDER BY month) AS prev_revenue
FROM monthly
ORDER BY month;
```

> [!TIP]
> 第一個月沒有「上月」，所以 `prev_revenue` 回傳 `NULL`。這是正常行為，後續計算環比時用 `NULLIF` 防除以零即可。

---

## 範例 2：計算月環比增長率

```sql run
WITH monthly AS (
  SELECT
    strftime('%Y-%m', order_date) AS month,
    SUM(total_amount)             AS revenue
  FROM orders
  WHERE status = 'completed'
  GROUP BY month
),
with_lag AS (
  SELECT
    month,
    revenue,
    LAG(revenue) OVER (ORDER BY month) AS prev_revenue
  FROM monthly
)
SELECT
  month,
  ROUND(revenue, 0)          AS revenue,
  ROUND(prev_revenue, 0)     AS prev_revenue,
  ROUND(
    (revenue - prev_revenue) / NULLIF(prev_revenue, 0) * 100,
    1
  )                          AS mom_growth_pct
FROM with_lag
ORDER BY month;
```

> [!WARN]
> 用 `NULLIF(prev_revenue, 0)` 防止除以零。若上月營收為 0，結果顯示 NULL 比顯示無意義的極大數字更安全。

## 範例 3：計算每位會員相鄰兩次購買的天數間隔

```sql run
WITH customer_orders AS (
  SELECT
    customer_id,
    order_id,
    order_date,
    LAG(order_date) OVER (
      PARTITION BY customer_id
      ORDER BY order_date, order_id
    ) AS prev_order_date
  FROM orders
  WHERE status = 'completed'
)
SELECT
  customer_id,
  order_id,
  order_date,
  prev_order_date,
  ROUND(
    julianday(order_date) - julianday(prev_order_date),
    0
  ) AS days_since_prev
FROM customer_orders
WHERE prev_order_date IS NOT NULL
ORDER BY customer_id, order_date
LIMIT 20;
```

> [!BIZ]
> `julianday()` 是 SQLite 計算日期差的標準方式，回傳浮點天數。兩個 `julianday` 相減直接得到相差天數，非常方便。

---

## 範例 4：LEAD — 找每張訂單後的下一張訂單

```sql run
WITH next_orders AS (
  SELECT
    customer_id,
    order_id,
    order_date,
    total_amount,
    LEAD(order_id)    OVER (PARTITION BY customer_id ORDER BY order_date, order_id) AS next_order_id,
    LEAD(order_date)  OVER (PARTITION BY customer_id ORDER BY order_date, order_id) AS next_order_date,
    LEAD(total_amount) OVER (PARTITION BY customer_id ORDER BY order_date, order_id) AS next_amount
  FROM orders
  WHERE status = 'completed'
)
SELECT *
FROM next_orders
WHERE next_order_id IS NOT NULL
ORDER BY customer_id, order_date
LIMIT 20;
```

> [!TIP]
> `LEAD` 常用於計算「從這次購買到下次購買」的時間窗口，或分析購買序列中下一個動作。最後一筆訂單的 `next_order_id` 自然為 NULL，代表該客戶尚未有下一次購買。

---

## 常見模式：CTE 彙總 → 視窗函數

處理時間序列資料時，幾乎都會用到這個模式：

```
原始明細表
  └─ CTE 彙總（GROUP BY 月份）
       └─ 外層視窗函數（LAG/LEAD）
            └─ 最終計算（環比、差值）
```

> [!DIALECT]
> **SQLite**：`julianday(date_string)` 計算日期差；日期字串需為 `YYYY-MM-DD` 格式。
> **PostgreSQL**：直接相減 `order_date - prev_order_date` 回傳 `INTERVAL`；或用 `EXTRACT(epoch FROM ...)/ 86400` 轉天數。
> **BigQuery**：`DATE_DIFF(order_date, prev_order_date, DAY)` 直接回傳整數天數。
