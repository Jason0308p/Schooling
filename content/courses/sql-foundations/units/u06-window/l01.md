# ROW_NUMBER、RANK、DENSE_RANK：排名函數

視窗函數（Window Function）讓你在**不壓縮列數**的情況下，對每一列計算「它在整個結果集中的排名」或「它與前後列的關係」。排名函數是最常見的入門應用。

> [!BIZ]
> 電商最常見的問題之一就是「找出 Top N」：哪些商品最暢銷？哪筆訂單金額最高？視窗排名函數讓你直接在 SELECT 中產生序號，再用外層過濾，比 `LIMIT` 更靈活。

---

## 語法基礎

```sql
排名函數() OVER (ORDER BY 欄位 DESC)
```

- `OVER (...)` 是視窗函數的核心語法，告訴資料庫「在哪個範圍上算」
- `ORDER BY` 決定排名依據
- 沒有 `PARTITION BY` 時，整張結果集視為同一組

---

## 三種排名函數的差異

假設有四個商品售價分別為 500、400、400、300：

| 函數 | 結果 | 說明 |
|------|------|------|
| `ROW_NUMBER()` | 1, 2, 3, 4 | 無論並列，給唯一流水號 |
| `RANK()` | 1, 2, 2, 4 | 並列後**跳號**（沒有第 3 名） |
| `DENSE_RANK()` | 1, 2, 2, 3 | 並列後**不跳號** |

---

## 範例 1：用 ROW_NUMBER 給 completed 訂單按金額排名

```sql run
SELECT
  ROW_NUMBER() OVER (ORDER BY total_amount DESC) AS rn,
  order_id,
  customer_id,
  order_date,
  total_amount
FROM orders
WHERE status = 'completed'
ORDER BY rn
LIMIT 20;
```

> [!TIP]
> `ROW_NUMBER()` 保證每列都有唯一的序號，即使兩筆訂單金額完全相同也不會重複。需要唯一主鍵或分頁時優先選它。

---

## 範例 2：三種排名函數對比

用 CTE 先準備資料，再用三種函數對比效果：

```sql run
WITH price_data AS (
  SELECT
    product_id,
    product_name,
    category,
    price
  FROM products
  WHERE is_active = 1
)
SELECT
  product_name,
  category,
  price,
  ROW_NUMBER() OVER (ORDER BY price DESC) AS row_num,
  RANK()       OVER (ORDER BY price DESC) AS rnk,
  DENSE_RANK() OVER (ORDER BY price DESC) AS dense_rnk
FROM price_data
ORDER BY price DESC
LIMIT 20;
```

> [!WARN]
> 同一個 `SELECT` 可以同時寫多個視窗函數，每個都帶自己的 `OVER (...)` 子句。它們互相獨立，對同一列分別計算，不會互相影響。

---

## 範例 3：用 RANK 找各分類中售價最高的商品

這裡先預覽 `PARTITION BY` 的概念（下一課詳解），讓你看到「分組排名」的威力：

```sql run
WITH ranked AS (
  SELECT
    product_name,
    category,
    price,
    RANK() OVER (PARTITION BY category ORDER BY price DESC) AS cat_rank
  FROM products
  WHERE is_active = 1
)
SELECT *
FROM ranked
WHERE cat_rank = 1
ORDER BY category;
```

> [!BIZ]
> 這個模式非常實用：先用視窗函數標記排名，外層再過濾 `WHERE rank = 1`。它比 `GROUP BY + MAX()` 更強大，因為你可以同時取出其他欄位（例如 product_id）。

---

## 範例 4：各銷售通路的前 3 名訂單

```sql run
WITH channel_ranked AS (
  SELECT
    ROW_NUMBER() OVER (
      PARTITION BY sales_channel
      ORDER BY total_amount DESC
    ) AS rn,
    order_id,
    sales_channel,
    order_date,
    total_amount
  FROM orders
  WHERE status = 'completed'
)
SELECT *
FROM channel_ranked
WHERE rn <= 3
ORDER BY sales_channel, rn;
```

> [!TIP]
> 在 SQL 中，視窗函數的計算發生在 `WHERE` 之後、`ORDER BY` 之前。所以不能在同一層 `WHERE` 過濾視窗函數的結果——必須用子查詢或 CTE 包一層。

---

## 何時選哪種排名函數？

| 情境 | 建議函數 |
|------|---------|
| 分頁、流水號、去重 | `ROW_NUMBER()` |
| 競賽排名（允許並列、跳號） | `RANK()` |
| 連續排名（允許並列、不跳號） | `DENSE_RANK()` |

> [!DIALECT]
> **SQLite**：3.25+ 完整支援三種函數，Schooling 使用的 sql.js 已符合需求。
> **PostgreSQL**：語法完全相同，另外支援 `PERCENT_RANK()`、`CUME_DIST()`。
> **BigQuery**：語法相同，但視窗函數在 `QUALIFY` 子句中可直接過濾（不需子查詢）：`QUALIFY ROW_NUMBER() OVER (...) = 1`。
