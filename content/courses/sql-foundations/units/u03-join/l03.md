## 三張表以上：一次接一張

要算「各商品分類賣了多少」，需要三張表：

- `order_items`：每個商品賣了幾件、成交單價（**金額和數量在這裡**）
- `orders`：這張訂單是不是成交（**狀態在這裡**）
- `products`：商品屬於哪個分類（**分類在這裡**）

```text
order_items ──(order_id)──▶ orders
     │
     └──(product_id)──▶ products
```

做法是從「最細的那張表」出發，**一次接一張**：

```sql run
SELECT
  p.category,
  SUM(oi.quantity * oi.unit_price) AS revenue
FROM order_items AS oi
JOIN orders   AS o ON o.order_id   = oi.order_id
JOIN products AS p ON p.product_id = oi.product_id
WHERE o.status = 'completed'
GROUP BY p.category
ORDER BY revenue DESC;
```

- 每一個 `JOIN` 都有自己的 `ON`。
- ON 的左右兩邊分別是「已經接進來的表」和「新接的表」的鍵。
- 營收是**明細層的**：`數量 × 成交單價`，再加總。

> [!TIP] 寫多表 JOIN 的步驟
> 1. 先決定「一列代表什麼」，也就是最終要分析的粒度（這題是「一個訂單明細」）。
> 2. 從那張表開始 `FROM`。
> 3. 缺什麼欄位，就 JOIN 哪張表。
> 4. 每接一張表，用 `COUNT(*)` 檢查列數有沒有異常變多。

## 最重要的陷阱：一對多讓金額被重複計算

一張訂單可以有**好幾個商品明細**。如果你把訂單表接上明細表，**訂單那一列會被複製很多份**，每份都帶著同樣的 `total_amount`。

先看正確的訂單總營收：

```sql run
SELECT SUM(total_amount) AS revenue
FROM orders
WHERE status = 'completed';
```

再看「順手」多 JOIN 一張明細表之後的結果：

```sql run
SELECT SUM(o.total_amount) AS revenue
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.order_id
WHERE o.status = 'completed';
```

第二個數字**明顯比較大**。原因：一張訂單有 3 個商品，就接出 3 列，`total_amount` 被加了 3 次。

用列數看得更清楚：

```sql run
SELECT
  (SELECT COUNT(*) FROM orders WHERE status = 'completed') AS orders_rows,
  (SELECT COUNT(*)
     FROM orders o
     JOIN order_items oi ON oi.order_id = o.order_id
    WHERE o.status = 'completed') AS joined_rows;
```

`joined_rows` 比 `orders_rows` 多，就是「訂單列被複製」的證據。

> [!WARN] 黃金法則：金額屬於哪一層，就只用那一層的欄位加總
> - `orders.total_amount` 是**訂單層**的金額。JOIN 了明細表之後就不能再加總它。
> - `quantity * unit_price` 是**明細層**的金額，JOIN 了明細表之後才能加總它。
> - 如果只是要「各城市的訂單營收」，**根本不需要 JOIN 明細表**。
>
> 判斷方法：JOIN 完之後，用 `COUNT(*)` 比較列數。列數變多 = 有一對多，原本的金額欄位就不能直接加。

> [!BIZ] 這個錯誤在職場上有多常見
> 報表數字「比財務對帳大一倍多」，一半以上是這個原因。看到數字偏高，第一個檢查：我是不是 JOIN 了一張「比我的分析粒度更細」的表？

## 要數「幾張訂單」「幾個人」：用 COUNT(DISTINCT)

當 JOIN 讓同一個訂單、同一位會員重複出現，要算「有幾個」就要去重：

```sql run
SELECT
  p.category,
  COUNT(*)                    AS item_rows,
  COUNT(DISTINCT oi.order_id) AS orders_containing
FROM order_items AS oi
JOIN orders   AS o ON o.order_id   = oi.order_id
JOIN products AS p ON p.product_id = oi.product_id
WHERE o.status = 'completed'
GROUP BY p.category
ORDER BY orders_containing DESC;
```

- `COUNT(*)`：這個分類出現在幾個**明細列**。
- `COUNT(DISTINCT oi.order_id)`：這個分類出現在幾**張訂單**。同一張訂單買了兩個保溫杯，只算 1。

行銷常見的問法「有幾位客人買過」「有幾張訂單用過折扣碼」，都是 `COUNT(DISTINCT ...)`。

> [!DIALECT] 多表 JOIN 的寫法
> 多個 `JOIN` 的寫法在各資料庫相同。唯一要注意：**BigQuery 的 GA4 資料裡，事件參數是巢狀欄位**，要用 `UNNEST` 展開，那不是 JOIN，而是另一種「把陣列展開成列」的語法，會在 BigQuery 延伸課程介紹。
