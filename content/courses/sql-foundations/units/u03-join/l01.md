## 為什麼需要 JOIN

前面的查詢都只用一張表。但真實的問題幾乎都跨表：

- 「各城市的營收」：城市在 `customers`，金額在 `orders`。
- 「各分類賣了多少」：分類在 `products`，數量在 `order_items`。
- 「各活動花了多少錢」：活動名稱在 `campaigns`，花費在 `ad_spend`。

資料庫把每件事分開存（第 0 單元講過：每件事只記在一個地方），**JOIN 就是把它們用共通的鍵接回來**。

## 第一個 INNER JOIN

```sql run
SELECT
  o.order_id,
  o.order_date,
  c.name,
  c.city
FROM orders AS o
JOIN customers AS c
  ON c.customer_id = o.customer_id
LIMIT 10;
```

拆開來看：

- `FROM orders AS o`：以訂單表為主，取別名 `o`。
- `JOIN customers AS c`：要接上會員表，取別名 `c`。
- `ON c.customer_id = o.customer_id`：**接起來的條件**。訂單裡的 `customer_id` 等於會員表的 `customer_id`，就是同一位會員。

資料庫會對 `orders` 的每一列，去 `customers` 找出符合 ON 條件的列，把兩邊的欄位併成一列。

> [!NOTE] JOIN 就是 INNER JOIN
> 單寫 `JOIN` 等於 `INNER JOIN`。意思是**兩邊都對得上的才留下**：對不到會員的訂單、沒有訂單的會員，都不會出現在結果裡。這個「會被丟掉的列」下一課會專門處理。

## 別名與欄位前綴

兩張表都有 `customer_id` 這個欄位。如果只寫 `customer_id`，資料庫不知道你指哪一張的：

```sql
SELECT customer_id FROM orders o JOIN customers c ON c.customer_id = o.customer_id;
-- ❌ ambiguous column name: customer_id
```

所以 JOIN 查詢裡的欄位**都寫成 `別名.欄位`**，例如 `o.order_id`、`c.name`。即使欄位名稱沒有衝突，也建議一律加前綴，讀的人一眼就知道這個欄位屬於哪張表。

> [!TIP] 別名取法
> 用表名的縮寫，一個字母或兩個字母都行：`orders o`、`customers c`、`order_items oi`、`products p`。不要取 `a`、`b`、`t1`、`t2` 這種沒有意義的名字，三張表以上就會看不懂。

## JOIN 之後照樣可以 WHERE、GROUP BY

JOIN 只是先把表接成一張「大表」，後面的篩選、分組、排序全部照舊：

```sql run
SELECT
  c.membership_tier,
  COUNT(*)           AS order_count,
  SUM(o.total_amount) AS revenue
FROM orders AS o
JOIN customers AS c
  ON c.customer_id = o.customer_id
WHERE o.status = 'completed'
GROUP BY c.membership_tier
ORDER BY revenue DESC;
```

這就是「各會員等級的營收」：等級來自會員表，金額和狀態來自訂單表。

## 檢查：JOIN 之後列數有沒有變？

養成習慣，JOIN 完先對一下列數。訂單和會員是「**多對一**」（很多張訂單屬於同一位會員），所以接完之後，列數應該**等於訂單數**，不多也不少：

```sql run
SELECT
  (SELECT COUNT(*) FROM orders) AS orders_rows,
  (SELECT COUNT(*)
     FROM orders o
     JOIN customers c ON c.customer_id = o.customer_id) AS joined_rows;
```

兩個數字相同，代表每張訂單都剛好對到一位會員。如果 `joined_rows` 比較少，代表有訂單對不到會員（資料有問題）；如果比較多，代表會員表的鍵有重複。

> [!BIZ] 對帳習慣
> 實務上，報表數字被質疑時，第一個動作就是「我 JOIN 之前和之後，列數和總金額有沒有變」。後面第 3 課會看到：**JOIN 之後金額悄悄變成兩倍**，是分析師最常見的錯誤之一。

> [!DIALECT] JOIN 的寫法差異
> `JOIN ... ON ...` 在 SQLite、PostgreSQL、MySQL、BigQuery 完全通用。
>
> - 兩張表的鍵**欄位名稱相同**時，PostgreSQL、MySQL、SQLite 可以寫 `JOIN customers USING (customer_id)`，省掉 ON。BigQuery 也支援 `USING`。
> - BigQuery 的表名要寫成 `` `專案.資料集.表` ``，例如 `` `my-project.shop.orders` ``，別名寫法一樣。
