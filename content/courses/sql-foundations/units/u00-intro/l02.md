## 情境：你剛入職「好禮客製」

整門課你都是「好禮客製」的數據分析師。這是一間賣客製化贈品的品牌，賣保溫杯、馬克杯、帆布袋、禮盒，有三個銷售通路：

- **online_store**：官網（Shopify 這類電商平台）
- **line_shop**：LINE 官方商店
- **b2b**：企業大量訂購，例如尾牙禮品、新人迎新禮

資料期間是 **2025-07-01 到 2026-06-30**，整整一年。禮品業有明顯的季節性：11、12 月是旺季，1 月有尾牙和春節。

## 八張資料表

| 資料表 | 中文 | 一列代表 | 類比你熟悉的工具 |
|---|---|---|---|
| `customers` | 會員 | 一位會員 | Shopify Customers / CRM |

隨時可以點右上角的 **「資料表」** 查看每張表有哪些欄位、各代表什麼。

## 表跟表怎麼連在一起：主鍵與外鍵

看看訂單跟會員的關係：

```text
customers                     orders
┌─────────────┬──────┐        ┌──────────┬─────────────┬──────────────┐
│ customer_id │ name │        │ order_id │ customer_id │ total_amount │
├─────────────┼──────┤        ├──────────┼─────────────┼──────────────┤
│ 7           │ 林怡君│ ◀──────│ 100012   │ 7           │ 1280         │
│             │      │ ◀──────│ 100340   │ 7           │ 560          │
└─────────────┴──────┘        └──────────┴─────────────┴──────────────┘
```

- `customers.customer_id` 是會員表的**主鍵（Primary Key）**：每位會員一個，不重複。
- `orders.customer_id` 是訂單表的**外鍵（Foreign Key）**：記錄「這張訂單是誰下的」，指回會員表。
- 一位會員可以有很多張訂單，這叫做**一對多**關係。

同理，一張訂單可以有多個商品，所以商品明細另外放在 `order_items`，用 `order_id` 指回訂單。

> [!BIZ] 為什麼不把所有東西放在同一張大表？
> 如果每筆訂單都把會員的姓名、email、城市抄一份，會員改 email 時就要改幾十個地方，漏改就會資料不一致。資料庫設計的原則是**每件事只記在一個地方**，要用的時候再用 JOIN 接起來（第 3 單元會教）。

## 看一下訂單長什麼樣子

```sql run
SELECT * FROM orders LIMIT 5;
```

注意這幾個欄位，後面的課會一直用到：

- `status`：只有 `completed` 是真正成交的訂單。算營收時通常要排除退款（refunded）和取消（cancelled）。
- `total_amount`：客人實付金額，已經扣掉折扣、加上運費。
- `coupon_code`：沒用折扣碼的話是 **NULL**（空值）。NULL 是 SQL 裡很重要的概念，第 1 單元會詳細講。

> [!WARN] 這份資料是「刻意不乾淨」的
> 真實工作的資料一定有問題，所以練習資料裡也藏了一些：有些會員沒填城市、有人把「台北市」寫成「臺北市」、有些 email 大小寫不一致或前後有空白。看到怪資料不用懷疑自己，後面會教你怎麼處理。
