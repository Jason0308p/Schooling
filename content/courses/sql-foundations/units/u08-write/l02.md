# INSERT：新增資料的正確方式

## INSERT 基本語法

```sql
INSERT INTO 表名 (欄位1, 欄位2, 欄位3)
VALUES (值1, 值2, 值3);
```

### ⚠️ 一定要指定欄位名稱

**不要**依賴欄位順序：

```sql
-- ❌ 危險寫法：依賴欄位順序
INSERT INTO products VALUES (999, 'SKU-999', '客製馬克杯', '杯具', 380, 150, '2026-06-01', 1);

-- ✅ 安全寫法：明確指定欄位
INSERT INTO products (product_id, sku, product_name, category, price, cost, launch_date, is_active)
VALUES (999, 'SKU-999', '客製馬克杯', '杯具', 380, 150, '2026-06-01', 1);
```

為什麼危險？因為資料表結構可能在未來變動（新增欄位、欄位順序調整），依賴順序的 INSERT 會靜悄悄地把資料寫進錯誤的欄位。

---

## 新增客戶的完整範例

```sql
INSERT INTO customers (
    customer_id,
    name,
    email,
    gender,
    birth_year,
    city,
    signup_date,
    acquisition_channel,
    membership_tier
)
VALUES (
    10001,
    '王小明',
    'xiaoming.wang@example.com',
    'M',
    1990,
    '台北市',
    '2026-06-15',
    'organic',
    '一般'
);
```

新增後，立刻用 SELECT 驗證：

```sql
SELECT customer_id, name, email, membership_tier
FROM customers
WHERE customer_id = 10001;
```

## INSERT 前的資料驗證

### 確認主鍵不衝突

在手動指定 `product_id` 前，先確認目前最大值：

```sql
SELECT MAX(product_id) AS max_id FROM products;
```

新的 `product_id` 應該是 `max_id + 1`（或更大）。

### 確認 UNIQUE 欄位不重複

email 通常有 UNIQUE 限制，新增前先查：

```sql
SELECT customer_id, name, email
FROM customers
WHERE email = 'xiaoming.wang@example.com';
```

若有結果，代表該 email 已存在，不應重複新增。

---

## INSERT OR IGNORE / INSERT OR REPLACE（SQLite）

當違反 UNIQUE 或主鍵約束時，SQLite 提供兩種處理方式：

```sql
-- 衝突就跳過，不報錯
INSERT OR IGNORE INTO customers (customer_id, name, email, ...)
VALUES (10001, '王小明', 'xiaoming.wang@example.com', ...);

-- 衝突就用新資料覆蓋舊資料
INSERT OR REPLACE INTO customers (customer_id, name, email, ...)
VALUES (10001, '王小明（更新）', 'xiaoming.wang@example.com', ...);
```

## INSERT INTO ... SELECT ...（從查詢結果新增）

這是 INSERT 最強大的用法：把一張表的查詢結果批量插入另一張表。

### 情境：把 VIP 客戶複製到 vip_snapshot 備份表

```sql
INSERT INTO vip_snapshot (customer_id, name, email, membership_tier, snapshot_date)
SELECT customer_id, name, email, membership_tier, DATE('now')
FROM customers
WHERE membership_tier = '金卡';
```

**欄位順序必須對應**：SELECT 的欄位順序要和 INSERT INTO 後面括號的欄位順序一致。

### 執行前，先用 SELECT 確認資料

```sql
-- 先確認哪些客戶會被複製
SELECT customer_id, name, email, membership_tier, DATE('now') AS snapshot_date
FROM customers
WHERE membership_tier = '金卡';
```

確認結果正確後，才執行 `INSERT INTO ... SELECT ...`。

---

## 資料完整性：INSERT 前的外鍵確認

在 orders 中新增訂單前，必須確認 `customer_id` 真的存在於 customers：

```sql
-- 確認 customer_id = 9999 是否存在
SELECT customer_id, name FROM customers WHERE customer_id = 9999;
```

若查無結果，不應新增這筆訂單，否則會產生「孤兒訂單」（orphan record）——沒有對應客戶的訂單，資料庫的完整性就破壞了。

---

## 小結

| 好習慣 | 說明 |
|--------|------|
| 明確指定欄位名稱 | 防止欄位順序變動導致錯誤 |
| INSERT 前 SELECT 確認主鍵 | 避免主鍵衝突 |
| INSERT 前 SELECT 確認外鍵 | 避免孤兒資料 |
| INSERT 後 SELECT 驗證 | 確認資料正確寫入 |
| 用 OR IGNORE / OR REPLACE | 優雅處理衝突 |
