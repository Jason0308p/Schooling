# Transaction 與索引基礎

## 為什麼需要 Transaction（交易）？

設想「好禮客製」的訂單建立流程，需要同時執行三個操作：

1. 在 `orders` 新增一筆訂單
2. 在 `order_items` 新增多筆訂單明細
3. 扣減庫存（假設有 inventory 表）

如果第 1 步成功、第 2 步失敗，資料庫裡就有一筆沒有明細的「空訂單」——這是嚴重的資料錯誤。

**Transaction 解決這個問題：要麼全部成功，要麼全部取消。**

---

## Transaction 語法

```sql
BEGIN TRANSACTION;

-- 操作 1
INSERT INTO orders (...) VALUES (...);

-- 操作 2
INSERT INTO order_items (...) VALUES (...);

-- 操作 3
INSERT INTO order_items (...) VALUES (...);

-- 全部成功，提交
COMMIT;

-- 任何一步出錯，撤銷全部
-- ROLLBACK;
```

---

## 原子性（Atomicity）

Transaction 保證**原子性**：一組操作視為一個不可分割的單元。

```
BEGIN → [操作A] → [操作B] → [操作C]
                                ↓
                     成功 → COMMIT（全部寫入）
                     失敗 → ROLLBACK（全部取消）
```

這是 ACID 特性中的 A（Atomicity）。

---

## 什麼時候需要 Transaction？

| 場景 | 原因 |
|------|------|
| 訂單建立（orders + order_items） | 必須同時成功 |
| 帳戶轉帳（A 扣款 + B 入帳） | 不能只做一半 |
| 庫存扣減 + 訂單確認 | 兩個表需要同步 |
| 批量 UPDATE 多張表 | 確保一致性 |

**單一操作不需要 Transaction**，但複雜的多步驟操作幾乎都需要。

---

## UPDATE + Transaction 實際範例

```sql
BEGIN TRANSACTION;

-- 確認影響範圍
SELECT order_id, status FROM orders WHERE status = 'pending' AND order_date < '2026-01-01';

-- 批量更新
UPDATE orders
SET status = 'cancelled'
WHERE status = 'pending'
  AND order_date < '2026-01-01';

-- 確認更新結果
SELECT COUNT(*) FROM orders WHERE status = 'cancelled' AND order_date < '2026-01-01';

COMMIT;
```

## 索引（Index）：加速查詢的關鍵

索引的概念和書本的目錄一樣——不用翻遍整本書，直接跳到對應頁碼。

### 建立索引語法

```sql
-- 基本語法
CREATE INDEX idx_名稱 ON 表名(欄位名);

-- 實際範例：為 orders 的 customer_id 建索引
CREATE INDEX idx_orders_customer_id ON orders(customer_id);

-- 複合索引：同時涵蓋兩個欄位
CREATE INDEX idx_orders_date_status ON orders(order_date, status);
```

---

## 哪些欄位適合建索引？

| 適合建索引 | 原因 |
|-----------|------|
| WHERE 常用的欄位 | 加速篩選 |
| JOIN 的關聯欄位 | 加速連接 |
| ORDER BY 的欄位 | 加速排序 |
| 外鍵欄位 | 加速完整性檢查 |

### 「好禮客製」適合建索引的欄位

```sql
CREATE INDEX idx_orders_customer_id   ON orders(customer_id);
CREATE INDEX idx_orders_order_date    ON orders(order_date);
CREATE INDEX idx_orders_status        ON orders(status);
CREATE INDEX idx_order_items_order_id ON order_items(order_id);
CREATE INDEX idx_products_category    ON products(category);
```

---

## 索引的代價

索引不是免費的：

| 代價 | 說明 |
|------|------|
| 寫入變慢 | 每次 INSERT/UPDATE/DELETE，索引都要更新 |
| 佔用磁碟空間 | 索引是額外的資料結構 |
| 維護成本 | 過多索引讓資料庫優化器更難選擇 |

**原則：只在真正需要的欄位建索引，別亂加。**

---

## EXPLAIN QUERY PLAN（診斷工具）

想知道 SQLite 有沒有用到索引：

```sql
EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 1001;
```

輸出中看到 `USING INDEX` 代表用到索引，`SCAN TABLE` 代表全表掃描（沒有索引）。

---

## 小結

### Transaction

- 保證多個操作「全部成功或全部失敗」
- 語法：`BEGIN TRANSACTION` → 操作 → `COMMIT` 或 `ROLLBACK`
- 適用場景：訂單建立、轉帳、批量更新多張表

### 索引

- 加速 WHERE、JOIN、ORDER BY 查詢
- 建在高頻查詢的欄位（尤其是外鍵、日期、狀態）
- 代價：寫入變慢、佔空間——按需建立，不要濫用
