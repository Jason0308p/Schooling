# 安全的 UPDATE：先 SELECT 再改

## 為什麼 UPDATE 很危險？

UPDATE 是 SQL 中最容易犯下「災難性錯誤」的語法。原因只有一個：

> **忘記寫 WHERE 條件 → 全表所有資料都被更新**

```sql
-- ⚠️ 危險：沒有 WHERE，所有商品都會下架
UPDATE products SET is_active = 0;

-- ✅ 正確：只下架指定類別
UPDATE products SET is_active = 0 WHERE category = '季節限定';
```

這個錯誤在生產環境發生過無數次，造成資料毀損、服務中斷。

---

## UPDATE 語法結構

```sql
UPDATE 表名
SET 欄位1 = 新值1,
    欄位2 = 新值2
WHERE 條件;
```

多個欄位用逗號分隔，WHERE 決定「哪些列要被更新」。

### 實際範例：調漲禮盒類商品 5% 價格

```sql
UPDATE products
SET price = price * 1.05
WHERE category = '禮盒'
  AND is_active = 1;
```

---

## 安全流程：先 SELECT 確認，再 UPDATE

**黃金原則：把 WHERE 條件先放進 SELECT，確認影響範圍正確，再執行 UPDATE。**

### Step 1：用 SELECT 確認影響的列

```sql
-- 先看看哪些商品會被影響
SELECT product_id, product_name, category, price
FROM products
WHERE category = '禮盒'
  AND is_active = 1
ORDER BY product_id;
```

執行這個查詢，眼睛確認：
- 筆數是否合理？
- 有沒有不該被影響的商品混進來？
- price 的當前值是否是預期的起始值？

### Step 2：確認無誤後執行 UPDATE

```sql
UPDATE products
SET price = price * 1.05
WHERE category = '禮盒'
  AND is_active = 1;
```

### Step 3：UPDATE 後再次 SELECT 驗證

```sql
-- 驗證價格是否正確更新
SELECT product_id, product_name, category, price
FROM products
WHERE category = '禮盒'
  AND is_active = 1
ORDER BY product_id;
```

---

## 用 Transaction 保護自己

即使操作正確，建議在重要的 UPDATE 前開啟交易：

```sql
BEGIN TRANSACTION;

-- 先 SELECT 確認
SELECT product_id, product_name, price
FROM products
WHERE category = '禮盒' AND is_active = 1;

-- 執行 UPDATE
UPDATE products
SET price = price * 1.05
WHERE category = '禮盒' AND is_active = 1;

-- 確認結果符合預期後
COMMIT;

-- 如果發現不對，執行這行撤銷
-- ROLLBACK;
```

`BEGIN TRANSACTION` 開始後，所有更動暫時保留在記憶體，`ROLLBACK` 可以完全還原，直到你 `COMMIT` 才真正寫入。

## 以 `is_active` 下架商品為例

「好禮客製」的商品管理使用軟刪除（soft delete）——不真正刪除資料，只把 `is_active` 設為 `0`。這樣保留了歷史訂單的完整性。

```sql
-- 下架商品前，先確認目標商品
SELECT product_id, product_name, is_active
FROM products
WHERE product_id IN (101, 205, 308);

-- 確認是這三個沒錯後，才執行
UPDATE products
SET is_active = 0
WHERE product_id IN (101, 205, 308);
```

**注意**：WHERE 用 `product_id IN (...)` 而非 `product_name = '...'`，因為主鍵是精確的，商品名稱可能有重複或打字錯誤。

---

## 小結

| 步驟 | 動作 | 目的 |
|------|------|------|
| 1 | SELECT + 相同 WHERE | 確認影響範圍 |
| 2 | 檢查筆數與資料 | 發現意外的命中 |
| 3 | BEGIN TRANSACTION | 為自己留後路 |
| 4 | 執行 UPDATE | 實際更新 |
| 5 | SELECT 驗證 | 確認結果正確 |
| 6 | COMMIT 或 ROLLBACK | 提交或撤銷 |
