# CREATE TABLE 與資料表設計

## CREATE TABLE 基本語法

```sql
CREATE TABLE 表名 (
    欄位名  資料型別  限制條件,
    欄位名  資料型別  限制條件,
    ...
);
```

---

## SQLite 常用資料型別

| 型別 | 用途 | 範例 |
|------|------|------|
| `INTEGER` | 整數 | customer_id, quantity |
| `REAL` | 浮點數 | price, cost |
| `TEXT` | 字串 / 日期 | name, email, order_date |
| `BLOB` | 二進位資料 | 圖片（通常不建議存 DB）|
| `NUMERIC` | 自動判斷 | 不建議使用，型別不明確 |

SQLite 的型別系統很寬鬆（型別親和性），但**命名要清晰**，讓人一眼看懂欄位的用途。

---

## 主鍵：每張表必備

```sql
-- INTEGER PRIMARY KEY 在 SQLite 中自動成為自增主鍵（rowid 的別名）
CREATE TABLE product_reviews (
    review_id   INTEGER PRIMARY KEY,
    ...
);
```

插入時不需要指定 `review_id`，SQLite 自動填入下一個整數。

---

## 常見限制條件

```sql
NOT NULL    -- 此欄位不可為空
DEFAULT 值  -- 未填時的預設值
UNIQUE      -- 此欄位值不可重複
CHECK(條件) -- 值必須滿足此條件
```

---

## 完整範例：建立 product_reviews 表

「好禮客製」想新增商品評論功能，設計一張 `product_reviews` 表：

```sql
CREATE TABLE product_reviews (
    review_id     INTEGER PRIMARY KEY,
    product_id    INTEGER NOT NULL,
    customer_id   INTEGER NOT NULL,
    rating        INTEGER NOT NULL CHECK(rating BETWEEN 1 AND 5),
    review_text   TEXT,
    review_date   TEXT NOT NULL DEFAULT (DATE('now')),
    is_verified   INTEGER NOT NULL DEFAULT 0,

    FOREIGN KEY (product_id)  REFERENCES products(product_id),
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

### 設計解析

| 欄位 | 設計決策 | 理由 |
|------|----------|------|
| `review_id` | INTEGER PRIMARY KEY | 自增，不需手動指定 |
| `product_id` | NOT NULL + FOREIGN KEY | 評論必須對應商品 |
| `customer_id` | NOT NULL + FOREIGN KEY | 評論必須對應客戶 |
| `rating` | CHECK(BETWEEN 1 AND 5) | 資料庫層面防止無效評分 |
| `review_text` | 無 NOT NULL | 允許只打星星不寫文字 |
| `review_date` | DEFAULT (DATE('now')) | 自動填入今日日期 |
| `is_verified` | DEFAULT 0 | 預設未驗證購買 |

---

## FOREIGN KEY 注意事項（SQLite）

SQLite 預設不啟用外鍵約束，需要手動開啟：

```sql
PRAGMA foreign_keys = ON;
```

開啟後，若違反外鍵約束（例如插入不存在的 `product_id`），會報錯並拒絕操作。

---

## 模擬 FOREIGN KEY 檢查

在沒有開啟 `PRAGMA foreign_keys` 的環境下，可以手動用 SELECT 確認：

```sql
-- 檢查 orders 中有哪些 customer_id 在 customers 不存在
SELECT o.order_id, o.customer_id
FROM orders o
LEFT JOIN customers c ON o.customer_id = c.customer_id
WHERE c.customer_id IS NULL
ORDER BY o.order_id;
```

若查詢有結果，代表資料已有完整性問題，需要修正後再建立外鍵。

## 資料表設計原則

### 1. 每張表只負責一件事

不好的設計：把客戶資訊和訂單資訊合在同一張表。  
好的設計：customers + orders 分開，用 customer_id 關聯。

### 2. 每張表必須有主鍵

沒有主鍵的表無法精確更新或刪除單一列，也很難與其他表 JOIN。

### 3. 欄位能 NULL 的要想清楚

「允許 NULL」的欄位代表「這個資訊可以不存在」。搞不清楚時，先設 `NOT NULL`，之後放寬比收緊容易。

### 4. 用外鍵保護資料完整性

外鍵讓資料庫幫你擋住「孤兒資料」——確保 orders 中每個 customer_id 都真實存在於 customers。

---

## 小結：好的資料表設計 Checklist

- [ ] 有明確的主鍵
- [ ] 不可為空的欄位都有 `NOT NULL`
- [ ] 有合理的 `DEFAULT` 值（避免 NULL 蔓延）
- [ ] 外鍵正確指向父表的主鍵
- [ ] 欄位名稱清晰、型別合適
- [ ] 建立前先思考：未來的查詢、JOIN、索引需求
