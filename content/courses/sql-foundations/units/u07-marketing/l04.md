## 廣告 ROAS 分析：花了多少錢，賺回多少？

ROAS（Return on Ad Spend，廣告投資報酬率）是數位行銷最重要的效益指標：

$$\text{ROAS} = \frac{\text{廣告帶來的營收}}{\text{廣告花費}}$$

ROAS = 3 表示每花 1 元廣告費，帶來 3 元營收。**業界普遍將 3 視為基本及格線。**

> [!BIZ]
> 好禮客製在 Google Ads、Meta Ads、LINE 和 Email 都有投放廣告活動。行銷主管想知道：哪個 campaign 的 ROAS 最高？哪個在燒錢卻沒帶來訂單？

## 資料鏈路：廣告 → Session → 訂單

分析廣告效益的關鍵在於串聯資料：

```
campaigns → ad_spend（花費）
campaigns → sessions → orders（帶來的營收）
```

`sessions` 資料表的 `campaign_id` 欄位記錄了「這個 session 是從哪個廣告活動進來的」。

## 各活動的廣告花費

```sql run
SELECT
  a.campaign_id,
  c.campaign_name,
  c.platform,
  ROUND(SUM(a.cost)) AS total_cost
FROM ad_spend a
JOIN campaigns c ON a.campaign_id = c.campaign_id
GROUP BY a.campaign_id, c.campaign_name, c.platform
ORDER BY total_cost DESC;
```

## 各活動帶來的訂單數和營收

本課自訂教學模型（不是 GA4 Last Click）：同會員的 completed 訂單，候選 session 必須 campaign_id 非 NULL，日期在訂單日前 30 個完整日（含第 30 日、不含訂單同日）。選 session_start 最大者，同時刻以 session_id DESC 決勝。每單只歸屬一個活動，無候選不歸因。使用全資料期間訂單及花費；資料起點附近可能缺窗前資料。

```sql run
WITH ranked_touches AS (
  SELECT o.order_id, o.total_amount, s.campaign_id,
    ROW_NUMBER() OVER (
      PARTITION BY o.order_id
      ORDER BY s.session_start DESC, s.session_id DESC
    ) AS touch_rank
  FROM orders o
  JOIN sessions s ON s.customer_id = o.customer_id
    AND DATE(s.session_start) >= DATE(o.order_date, '-30 days')
    AND DATE(s.session_start) < DATE(o.order_date)
  WHERE o.status = 'completed' AND s.campaign_id IS NOT NULL
),
winners AS (
  SELECT order_id, total_amount, campaign_id
  FROM ranked_touches WHERE touch_rank = 1
)
SELECT campaign_id, COUNT(*) AS attributed_orders,
  ROUND(SUM(total_amount)) AS attributed_revenue
FROM winners
GROUP BY campaign_id
ORDER BY attributed_revenue DESC, campaign_id ASC;
```

> [!WARN]
> 先在 order_id 粒度選 winner，再 SUM。COUNT(DISTINCT order_id) 不能保護 SUM；SUM(DISTINCT total_amount) 會錯刪同額不同訂單。這不是因果效果或 GA4 last-touch。

## 合併計算 ROAS

```sql run
WITH ranked_touches AS (
  SELECT o.order_id, o.total_amount, s.campaign_id,
    ROW_NUMBER() OVER (
      PARTITION BY o.order_id
      ORDER BY s.session_start DESC, s.session_id DESC
    ) AS touch_rank
  FROM orders o
  JOIN sessions s ON s.customer_id = o.customer_id
    AND DATE(s.session_start) >= DATE(o.order_date, '-30 days')
    AND DATE(s.session_start) < DATE(o.order_date)
  WHERE o.status = 'completed' AND s.campaign_id IS NOT NULL
),
winners AS (
  SELECT order_id, total_amount, campaign_id
  FROM ranked_touches WHERE touch_rank = 1
),
spend AS (
  SELECT c.campaign_id, c.campaign_name, c.platform,
    ROUND(SUM(a.cost)) AS total_cost
  FROM campaigns c JOIN ad_spend a ON a.campaign_id = c.campaign_id
  GROUP BY c.campaign_id, c.campaign_name, c.platform
),
revenue AS (
  SELECT campaign_id, ROUND(SUM(total_amount)) AS attributed_revenue
  FROM winners GROUP BY campaign_id
)
SELECT sp.campaign_name, sp.platform, sp.total_cost,
  COALESCE(rv.attributed_revenue, 0) AS attributed_revenue,
  ROUND(COALESCE(rv.attributed_revenue, 0) * 1.0 / NULLIF(sp.total_cost, 0), 2) AS roas
FROM spend sp LEFT JOIN revenue rv ON rv.campaign_id = sp.campaign_id
WHERE sp.total_cost > 0
ORDER BY roas DESC NULLS LAST, sp.campaign_id ASC;
```

> [!TIP]
> `NULLIF(total_cost, 0)` 讓分母為零時回傳 NULL，避免除以零錯誤。`NULLS LAST` 確保 ROAS 無法計算的活動排在最後。

> [!DIALECT]
> SQLite 3.30+、PostgreSQL 支援 `NULLS LAST`；MySQL（含 8.x）不支援此語法，可用 `ORDER BY roas IS NULL, roas DESC`。SQLite 的 DESC 預設已將 NULL 排在最後，這裡是明示意圖。官方依據：[SQLite SELECT](https://www.sqlite.org/lang_select.html)、[MySQL SELECT 語法](https://dev.mysql.com/doc/refman/8.4/en/select.html)。
