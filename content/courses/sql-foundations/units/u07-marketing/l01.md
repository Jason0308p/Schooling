## 轉換漏斗：用 SQL 看清楚使用者旅程

轉換漏斗（Conversion Funnel）是電商最核心的分析工具之一。它幫助我們回答一個關鍵問題：**從進站到購買，每一步流失了多少人？**

> [!BIZ]
> 好禮客製的 `events` 資料表記錄了每個 session 發生的行為事件。漏斗分析的目標是找出哪個環節流失最嚴重，優先改善那個步驟往往能帶來最大的業績提升。

## 認識事件資料

`events` 資料表包含以下 event_name：

| event_name | 意義 |
|---|---|
| `page_view` | 瀏覽任一頁面 |
| `view_item` | 查看商品頁 |
| `add_to_cart` | 加入購物車 |
| `begin_checkout` | 開始結帳 |
| `purchase` | 完成購買 |

先來看看各事件的整體分佈：

```sql run
SELECT
  event_name,
  COUNT(*) AS event_count,
  COUNT(DISTINCT session_id) AS unique_sessions
FROM events
GROUP BY event_name
ORDER BY event_count DESC;
```

## 為什麼用 session 而不用 event 計數？

同一個 session 可能發生多次 `page_view`，如果直接計數 event，同一個人的多次點擊會被重複計算，高估了漏斗頂部的流量。

> [!WARN]
> 漏斗分析要用 `COUNT(DISTINCT session_id)`，確保每個 session 只計算一次。否則轉換率會被嚴重低估。

## 用 CTE 建立漏斗

分步驟計算更清晰。先用 CTE 算出各階段的不重複 session 數：

```sql run
WITH funnel AS (
  SELECT
    event_name,
    COUNT(DISTINCT session_id) AS sessions
  FROM events
  WHERE event_name IN ('page_view', 'view_item', 'add_to_cart', 'begin_checkout', 'purchase')
  GROUP BY event_name
)
SELECT
  CASE event_name
    WHEN 'page_view'       THEN 1
    WHEN 'view_item'       THEN 2
    WHEN 'add_to_cart'     THEN 3
    WHEN 'begin_checkout'  THEN 4
    WHEN 'purchase'        THEN 5
  END AS step,
  event_name,
  sessions
FROM funnel
ORDER BY step;
```

## 加上轉換率

轉換率 = 下一階段 session 數 ÷ 上一階段 session 數 × 100

用 `LAG()` 取上一行的數值，`NULLIF` 防止除以零：

```sql run
WITH funnel AS (
  SELECT
    CASE event_name
      WHEN 'page_view'       THEN 1
      WHEN 'view_item'       THEN 2
      WHEN 'add_to_cart'     THEN 3
      WHEN 'begin_checkout'  THEN 4
      WHEN 'purchase'        THEN 5
    END AS step,
    event_name,
    COUNT(DISTINCT session_id) AS sessions
  FROM events
  WHERE event_name IN ('page_view', 'view_item', 'add_to_cart', 'begin_checkout', 'purchase')
  GROUP BY event_name
),
funnel_with_rate AS (
  SELECT
    step,
    event_name,
    sessions,
    LAG(sessions) OVER (ORDER BY step) AS prev_sessions
  FROM funnel
)
SELECT
  step,
  event_name,
  sessions,
  ROUND(
    sessions * 100.0 / NULLIF(prev_sessions, 0),
    1
  ) AS conv_rate
FROM funnel_with_rate
ORDER BY step;
```

> [!TIP]
> 第一步（`page_view`）沒有前一步，`LAG()` 回傳 NULL，所以 `conv_rate` 自然是 NULL，這是預期行為。

> [!DIALECT]
> `NULLIF(x, 0)` 當 x=0 時回傳 NULL，讓除法結果為 NULL 而非錯誤。這是跨資料庫通用的防除零技巧。
