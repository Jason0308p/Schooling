## 日期存成字串，照樣可以分析

SQLite 沒有原生的 Date 類型——日期存成 `TEXT`（格式 `YYYY-MM-DD`）。
只要格式一致，`strftime` 就能解析，字串比較（`>`, `<`, `BETWEEN`）也能正確按時間順序運作。

## strftime：格式化日期字串

`strftime(格式, 日期字串)` 從日期中取出你要的部分：

| 格式符號 | 意義 | 範例結果 |
|---------|------|---------|
| `%Y` | 四位年份 | `2026` |
| `%m` | 兩位月份 | `01`～`12` |
| `%Y-%m` | 年-月 | `2026-01` |
| `%d` | 兩位日期 | `01`～`31` |
| `%W` | 一年中的第幾週（週日為週首） | `00`～`53` |
| `%w` | 星期幾（0=週日） | `0`～`6` |

## 範例 1：月營收趨勢

```sql run
SELECT
  strftime('%Y-%m', order_date) AS month,
  COUNT(*)                      AS order_count,
  ROUND(SUM(total_amount))      AS revenue
FROM orders
WHERE status = 'completed'
GROUP BY month
ORDER BY month;
```

## 日期加減：date() 函數

`date(日期字串, '修飾符')` 可以做日期加減：

```
date('2026-06-30', '-30 days')   → 2026-05-31
date('2026-01-01', '+1 month')   → 2026-02-01
date('2026-06-30', 'start of month')  → 2026-06-01
```

### 範例 2：最近 30 天的每日訂單數

```sql run
SELECT
  order_date,
  COUNT(*) AS daily_orders
FROM orders
WHERE status = 'completed'
  AND order_date >= date('2026-06-30', '-29 days')
GROUP BY order_date
ORDER BY order_date;
```

> [!TIP]
> `'-29 days'` 加上當天本身，剛好是 30 天：`2026-06-01` 到 `2026-06-30`（含兩端）。
> 用 `>= date(..., '-29 days')` 而不是 `> date(..., '-30 days')` 可以避免邊界混淆。

## julianday：計算天數差

`julianday(日期)` 把日期轉成一個浮點數（儒略日），相減就得到**天數差**：

```sql run
SELECT
  customer_id,
  name,
  signup_date,
  CAST(julianday('2026-06-30') - julianday(signup_date) AS INTEGER) AS member_days
FROM customers
ORDER BY member_days DESC
LIMIT 10;
```

## 按季彙總

SQLite 沒有原生的「取季」函數，用 `CASE WHEN` 搭配 `strftime('%m')` 自行定義：

```sql run
SELECT
  CASE
    WHEN strftime('%m', order_date) BETWEEN '01' AND '03' THEN 'Q1'
    WHEN strftime('%m', order_date) BETWEEN '04' AND '06' THEN 'Q2'
    WHEN strftime('%m', order_date) BETWEEN '07' AND '09' THEN 'Q3'
    ELSE 'Q4'
  END AS quarter,
  COUNT(*)                 AS order_count,
  ROUND(SUM(total_amount)) AS revenue
FROM orders
WHERE status = 'completed'
GROUP BY quarter
ORDER BY quarter;
```

> [!WARN]
> `strftime('%m', ...)` 回傳的是**字串**，例如 `'07'`，不是數字 `7`。
> `BETWEEN '01' AND '03'` 是字串比較，剛好對齊兩位月份的格式——沒問題。
> 但若寫 `BETWEEN 1 AND 3`（數字），SQLite 會隱含轉型，部分情況可能得到意外結果，建議保持字串比較。

> [!DIALECT]
> **SQLite**：日期函數有 `strftime`、`date`、`time`、`datetime`、`julianday`。無原生 date/timestamp 類型；以文字或 Unix timestamp 儲存。
>
> **PostgreSQL**：有原生 `DATE`、`TIMESTAMP` 類型；`EXTRACT(MONTH FROM col)`、`DATE_TRUNC('month', col)` 是慣用語；`AGE(timestamp1, timestamp2)` 計算時間差；`NOW()` 取現在時間。
>
> **MySQL**：`YEAR(col)`、`MONTH(col)`、`DATE_FORMAT(col, '%Y-%m')` 常用；`DATEDIFF(d1, d2)` 計算天數差。
>
> **BigQuery**：有 `DATE_TRUNC(col, MONTH)`、`EXTRACT(QUARTER FROM col)`、`DATE_DIFF(d1, d2, DAY)`；`CURRENT_DATE()` 取今日；`FORMAT_DATE('%Y-%m', col)` 格式化。
