## 以空間換查找時間

客服要看每個問題代碼出現幾次。每遇到一個代碼就重新掃描整張清單會重複工作；用 Map 以代碼為鍵儲存目前計數，一次走完即可。

```js
function frequencies(codes) {
  const counts = new Map();
  for (const code of codes) {
    counts.set(code, (counts.get(code) ?? 0) + 1);
  }
  return counts;
}
const counts = frequencies(['late', 'refund', 'late']);
console.log(counts.get('late')); // 2
console.log(counts.get('missing') ?? 0); // 0
```

`?? 0` 只在查不到（undefined）時補零，不會把合法的 0 誤當作未設定。若輸入 n 筆、不同鍵 k 個，平均或常見雜湊模型下時間 O(n)、空間 O(k)；不能保證每一次雜湊操作在所有對抗性輸入都嚴格 O(1)，也不應承諾特定 JS 引擎的碰撞處理方式。

## 鍵是否真的相同？

```js
const a = { id: 7 };
const b = { id: 7 };
const byObject = new Map([[a, '已處理']]);
console.log(byObject.get(b)); // undefined
const byId = new Map([[a.id, '已處理']]);
console.log(byId.get(b.id)); // 已處理
```

物件以參照辨識，內容看起來相同不會自動合併。若業務規則要依 `id` 合併，就明確以穩定的基本型別 ID 作鍵。數字 7 與字串 '7' 也不是同一個鍵。若 ID 可能缺失，先驗證再計數，避免所有 undefined 都進同一桶。

> [!BIZ] 工作情境
> 日誌聚合常先正規化事件代碼，例如明確決定是否大小寫不敏感；不要在不同步驟有時轉小寫、有時不轉。

## 口頭說明與邊界

面試時說：「我需要按鍵增量統計，選 Map；單次查找採平均 O(1) 的模型，所以總計平均 O(n)、空間 O(k)。先釐清鍵的正規化與物件參照。」接著測空清單（空 Map）、全部相同（k=1）、全部不同（k=n），再問是否需要保留首次出現順序。Map 可迭代鍵值，但別把「插入順序」誤當成「按頻率排序」。
