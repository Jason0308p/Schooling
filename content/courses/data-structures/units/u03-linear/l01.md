## 先問取出順序

瀏覽器的返回紀錄常先處理最近一步；任務排隊則要先處理最早進來的一筆。前者是堆疊 LIFO，後者是佇列 FIFO。這是操作契約，不是程式語言內建容器名稱。

```js
const history = [];
history.push('首頁');
history.push('商品頁');
console.log(history.pop()); // 商品頁
console.log(history.pop()); // 首頁
```

使用陣列末端 push/pop 建堆疊，常見動態陣列模型下攤銷 O(1)。括號配對也是堆疊應用：讀到開括號就記錄，遇到關括號先檢查頂端是否匹配；只計數不夠，因為 `([)]` 數量相等但順序錯。

## 佇列不要一直 shift

```js
function processInOrder(tasks) {
  const queue = [...tasks];
  let head = 0;
  const result = [];
  while (head < queue.length) {
    const task = queue[head++];
    result.push(`完成:${task}`);
  }
  return result;
}
console.log(processInOrder(['備份', '通知']));
// ['完成:備份', '完成:通知']
```

`shift()` 從陣列開頭移除時，在通常陣列實作中可能搬動剩下的元素；反覆 shift 可能造成二次方總成本。head 索引讓每次讀取是 O(1)，整批處理 O(n)，但已讀元素仍留在 queue，長時間運作的服務應定期壓縮前綴或改用鏈結結構。上例複製輸入、產生結果，所以額外空間 O(n)；若只做副作用而不保留結果，空間分析會不同。

> [!TIP] 空佇列
> `head === queue.length` 代表沒有待處理項目；不要用元素真值判斷是否為空，因為 0、false 也是合法資料。

## 面試口頭推理

先講需求的順序，再講 API 與成本：「返回用堆疊，工作排程用 FIFO；在 JS 使用 head 避開前端刪除成本。」拿三筆任務模擬入隊 A、B、C，取兩次應是 A、B；拿空任務測試不應拋錯。若需要不斷長期入隊，補充資料保留與記憶體回收策略。
