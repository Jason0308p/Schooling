## 為什麼陣列是第一個選擇

商品列表、時間序列、搜尋結果都需要依位置讀取。JavaScript 陣列讓你以索引存取元素；但「能直接讀第 100 筆」不代表「能在最前面免費插入」。面試時先問資料是否已排序、能不能改動原陣列，才選演算法。

## 索引與搬移

```js
const prices = [120, 80, 200];
console.log(prices[1]); // 80
prices.splice(1, 0, 90); // [120, 90, 80, 200]
```

索引讀取通常視為 O(1)。中間插入需要搬動後續元素，最壞 O(n)；`push` 在一般動態陣列模型下是攤銷 O(1)，擴容那一次仍可能 O(n)。不能把每次 push 都稱為嚴格 O(1)。從頭找某值需 O(n)，不要混淆「索引」和「依值搜尋」。

## 已排序陣列的雙指標

假設數列遞增，要找和為 11 的兩個值。左端 2、右端 9 相加剛好；若和太小，只能增加左端（右端往左只會更小）；若和太大，就減少右端。這個單調性是移動指標的理由，不是背誦口訣。

```js
function pairWithSum(sorted, target) {
  let left = 0, right = sorted.length - 1;
  while (left < right) {
    const sum = sorted[left] + sorted[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
  }
  return null;
}
console.log(pairWithSum([2, 4, 7, 9], 11)); // [0, 3]
console.log(pairWithSum([2, 4, 7, 9], 20)); // null
```

兩個指標合計最多向內移動 n−1 次，時間 O(n)、額外空間 O(1)，回傳的是索引。排序若尚未完成，先排序通常要 O(n log n)，而且可能失去原索引；不可直接宣稱整體 O(n)。空陣列、一個元素都會回傳 null；`left < right` 保證不會拿同一個位置兩次。

> [!WARN] 邊界與假設
> 若輸入未排序，向內移動無法安全排除候選；若數值可能超過精確整數範圍，JavaScript Number 相加也可能不可靠。

## 口頭推理練習

對面試官先說：「輸入已排序，我從兩端開始，和小就提高下界，和大就降低上界；每輪排除至少一個位置。」接著用 `[2, 4, 7, 9]` 和目標 13 走一次：2+9 太小，改成 4+9 即命中。最後補上空陣列、重複值與沒有解的測試，再說明若不保證排序會換用 Map 或先排序。
