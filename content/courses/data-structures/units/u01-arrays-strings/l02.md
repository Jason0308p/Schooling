## 字串不是可隨意修改的陣列

清理產品代碼、檢查輸入或組合報表標題時，常要逐字掃描。JavaScript 字串不可變：修改位置不是就地改字元，而是產生新字串；先定義你所謂的「字元」再寫迴圈。

```js
const code = 'AB-12';
console.log(code[0]); // A
console.log(code.slice(0, 2)); // AB
console.log(code); // 原字串不變
```

以 `length` 和 `s[i]` 走訪的是 UTF-16 code unit。常見英文字母是一個單位，但 `😀`.length 是 2；`Array.from('😀')` 得到一個 code point。即使如此，組合式字元（例如字母加重音）也可能由多個 code point 組成；若需求是使用者眼中的字形，須另外定義分詞方式。

## 一次掃描：統計 ASCII 數字

明確限定輸入格式為 ASCII 數字 0 到 9，避免把其他文字系統的數字混入規格。

```js
function countAsciiDigits(text) {
  let count = 0;
  for (const ch of text) {
    if (ch >= '0' && ch <= '9') count++;
  }
  return count;
}
console.log(countAsciiDigits('訂單 A-204')); // 3
console.log(countAsciiDigits('')); // 0
```

這裡 `for...of` 逐 code point；時間 O(n)，n 以輸入的 UTF-16 長度衡量仍是線性的；額外空間 O(1)。規格若要包含全形數字，判斷條件就必須改，而不是悄悄宣稱已支援。

## 多段輸出：先收集再組裝

```js
function csvLine(fields) {
  return fields.map(value => String(value)).join(',');
}
console.log(csvLine(['A', 12, 'ready'])); // A,12,ready
```

這個簡化範例只適用欄位不含逗號、引號或換行的情況；真正 CSV 要做跳脫。`map` 產生片段陣列，最後 `join` 一次，避免刻意在每一輪重建逐漸變長的完整前綴。時間至少 O(總輸出長度 + 欄位數)，額外空間包含片段陣列與結果字串。不要保證 JS 引擎對反覆 `+=` 一定是平方時間：實作可能最佳化；面試要說的是避免依賴這種最佳化。

> [!TIP] 面試表述
> 先說清楚以 code unit、code point 還是可見字形為單位；再用空字串、表情符號與含分隔符的欄位檢驗規格。
