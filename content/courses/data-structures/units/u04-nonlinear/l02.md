## 要一直取「最急」而非整批排序

客服工單持續進來，每次要取優先度最高的一筆。每次排序整個列表太浪費；最小堆積可讓最小鍵留在根。堆積不是已排序陣列：除了父子間的大小限制，兄弟與不同分支不保證全域次序。

完全二元樹可存在陣列中。索引 i 的父節點是 `Math.floor((i-1)/2)`，左、右孩子是 `2*i+1`、`2*i+2`。插入先放末端，再一路向上交換直到父節點不大於它。

```js
function pushMin(heap, value) {
  heap.push(value);
  let i = heap.length - 1;
  while (i > 0) {
    const parent = Math.floor((i - 1) / 2);
    if (heap[parent] <= heap[i]) break;
    [heap[parent], heap[i]] = [heap[i], heap[parent]];
    i = parent;
  }
}
const heap = [];
for (const priority of [8, 3, 5, 1]) pushMin(heap, priority);
console.log(heap[0]); // 1
console.log(heap); // [1, 3, 5, 8]（此輸入的結果，非一般排序保證）
```

每次上移最多經過樹高 O(log n)，插入最壞 O(log n)；看根 O(1)（空堆時是 undefined），儲存 n 個元素 O(n)。取出根後應以末端元素補根，再向下與較小孩子交換，最壞 O(log n)；只做 `shift()` 不會維持堆積操作成本。

> [!NOTE] 相同優先度
> 只以數值比較時，相同優先度的處理順序沒有 FIFO 保證。若要穩定順序，連同遞增序號一起比較；也要事先決定是數值越小越急，還是越大越急。

## 口頭推理

拿 `[8,3,5,1]` 逐筆插入：8 成根，3 與 8 交換，5 不動，1 先越過 8 再越過 3。說清楚只有父子關係被約束，不能讀 `heap[1]` 就認定是全體第二小。測空堆、重複值、負數與單元素；若需求只有一次性排序輸出，也許直接排序比維護堆積更簡單。
