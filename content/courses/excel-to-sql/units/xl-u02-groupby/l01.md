## 樞紐分析表做了什麼？

在 Excel 裡建立樞紐分析表，你做的其實是：

1. 把一個欄位拉到**列區域**（例如「銷售通路」）
2. 把另一個欄位拉到**值區域**，選「加總」或「計數」（例如「訂單金額的加總」）
3. 按下確定，Excel 把資料壓扁成彙總報表

SQL 的 `GROUP BY` 做的是完全一樣的事，只是用文字描述。

## GROUP BY 的結構

```sql run
SELECT sales_channel, COUNT(*) AS order_count
FROM orders
GROUP BY sales_channel;
```

對照樞紐分析表：
- `GROUP BY sales_channel` = 把「銷售通路」拉到**列區域**
- `COUNT(*)` = 值欄位選**計數**
- `SUM(total_amount)` = 值欄位選**加總**

> [!TIP] 給 Excel 用戶的小提示
> `GROUP BY` 後面的欄位，就是你在 SELECT 裡**沒有**套聚合函數的欄位。規則很簡單：「只要出現在 SELECT 裡、沒有包在 COUNT/SUM/AVG 裡的欄位，都要放進 GROUP BY。」

## 常用聚合函數

| Excel 值欄位 | SQL 函數 | 說明 |
|---|---|---|
| 計數 | `COUNT(*)` | 算列數（含 NULL）|
| 計數（不含空值）| `COUNT(欄位名)` | 只算非 NULL 的列 |
| 加總 | `SUM(欄位名)` | 把數字加起來 |
| 平均 | `AVG(欄位名)` | 算平均值 |
| 最大值 | `MAX(欄位名)` | 找最大的 |
| 最小值 | `MIN(欄位名)` | 找最小的 |

```sql run
SELECT
  membership_tier,
  COUNT(*) AS member_count,
  AVG(1) AS placeholder
FROM customers
GROUP BY membership_tier;
```

## GROUP BY 之前先篩資料

如果只想對部分資料做樞紐，就先用 WHERE 篩選，再 GROUP BY：

```sql run
SELECT
  strftime('%Y-%m', order_date) AS month,
  SUM(total_amount) AS revenue
FROM orders
WHERE status = 'completed'
GROUP BY month
ORDER BY month;
```

這等於「先在 Excel 用篩選器只留下已完成的訂單，再建立樞紐分析表」。

> [!BIZ] 為什麼 SQL 比 Excel 更適合這個情境
> Excel 的樞紐分析表數據量一大就變慢。SQL 在資料庫端計算，你的電腦只收到結果；百萬列的資料，SQL 幾秒出結果，Excel 可能要轉很久甚至當掉。

> [!DIALECT] strftime 的寫法差異
> 截取年月的函數各家不同：
> | 資料庫 | 寫法 |
> |---|---|
> | SQLite | `strftime('%Y-%m', order_date)` |
> | PostgreSQL | `TO_CHAR(order_date, 'YYYY-MM')` 或 `DATE_TRUNC('month', order_date)` |
> | BigQuery | `FORMAT_DATE('%Y-%m', order_date)` 或 `DATE_TRUNC(order_date, MONTH)` |
> | MySQL | `DATE_FORMAT(order_date, '%Y-%m')` |
