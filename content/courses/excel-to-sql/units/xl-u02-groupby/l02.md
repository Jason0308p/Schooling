## 樞紐分析表的「值篩選器」

在 Excel 裡，你可以在樞紐分析表的值欄位上按右鍵，選「值篩選」→「大於…」，只留下符合條件的列。

SQL 用 `HAVING` 做同樣的事：

```sql run
SELECT
  strftime('%Y-%m', order_date) AS month,
  COUNT(*) AS order_count
FROM orders
GROUP BY month
HAVING order_count > 100
ORDER BY order_count DESC;
```

## WHERE vs HAVING：一定要分清楚

這是 SQL 最容易搞混的地方。

| | WHERE | HAVING |
|---|---|---|
| 在哪個階段過濾 | 彙總**之前** | 彙總**之後** |
| 能用聚合函數嗎 | ❌ 不行 | ✅ 可以 |
| 對應 Excel 操作 | 建樞紐分析表之前先篩選資料 | 在樞紐分析表上設值篩選器 |

```sql run
SELECT
  sales_channel,
  COUNT(*) AS order_count,
  SUM(total_amount) AS revenue
FROM orders
WHERE status = 'completed'
GROUP BY sales_channel
HAVING order_count >= 50
ORDER BY revenue DESC;
```

> [!TIP] 給 Excel 用戶的小提示
> 記憶技巧：WHERE 過濾「原始資料的列」，HAVING 過濾「彙總後的結果列」。不確定要用哪個？問自己「這個條件是要篩明細還是篩報表數字？」

## 同時算多個聚合值

樞紐分析表可以在值區域放多個欄位，SQL 也可以在一個查詢裡算多個聚合：

```sql run
SELECT
  sales_channel,
  COUNT(*) AS order_count,
  SUM(total_amount) AS revenue,
  ROUND(AVG(total_amount), 0) AS avg_order_value,
  MAX(total_amount) AS max_order,
  MIN(total_amount) AS min_order
FROM orders
WHERE status = 'completed'
GROUP BY sales_channel
ORDER BY revenue DESC;
```

> [!BIZ] 為什麼 SQL 比 Excel 更適合這個情境
> Excel 的樞紐分析表要切換「值顯示方式」才能同時看計數和加總，還要手動排版。SQL 直接在 SELECT 裡列出所有你要的指標，一次輸出，格式固定，再交給視覺化工具（Looker Studio、Tableau）畫圖。

> [!DIALECT] HAVING 是標準語法
> HAVING 在 SQLite、PostgreSQL、MySQL、BigQuery 語法完全相同。這個關鍵字 1970 年代就定下來了，到現在都沒變。
