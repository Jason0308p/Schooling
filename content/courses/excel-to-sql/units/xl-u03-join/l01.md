## VLOOKUP 在做什麼？

你在 Excel 用 VLOOKUP 時做的是：「在另一張表裡，找到 A 欄對得上的那一列，把第 N 欄的值拿過來。」

```
=VLOOKUP(A2, 客戶資料表, 3, 0)
```

SQL 的 JOIN 做完全一樣的事，只是更強大。

## INNER JOIN：找得到才留下

```sql run
SELECT o.order_id, o.order_date, c.name, o.total_amount
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
LIMIT 10;
```

解讀：
- `FROM orders o`：主表是 orders，簡稱 `o`
- `JOIN customers c`：把 customers 表加進來，簡稱 `c`
- `ON o.customer_id = c.customer_id`：兩張表的「共同欄位」，就是 VLOOKUP 的第一個參數（查找值）和查找範圍
- 兩邊都有 `customer_id` 欄位，所以要用「`表別名.欄位名`」的格式區分

> [!TIP] 給 Excel 用戶的小提示
> VLOOKUP 的「查找值」和「查找範圍的第一欄」就是 JOIN 的 ON 條件。`VLOOKUP(A2, 客戶表, ..., 0)` 等於 `JOIN 客戶表 ON 訂單.customer_id = 客戶表.customer_id`。

## 為什麼 JOIN 比 VLOOKUP 更可靠

| | VLOOKUP | SQL JOIN |
|---|---|---|
| 資料更新後 | 要重新拖公式 | 自動反映 |
| 資料量 | 幾萬列就開始卡 | 億列也沒問題 |
| 多個條件 | VLOOKUP 做不到，要用 INDEX-MATCH | `ON A.x = B.x AND A.y = B.y` |
| 容不容易出錯 | 拖錯欄位就錯 | 邏輯寫在 ON，可以被 review |

> [!BIZ] 為什麼 SQL 比 Excel 更適合這個情境
> VLOOKUP 最大的問題是「欄位號碼」：`VLOOKUP(A2, 客戶表, 3, 0)` 的「3」代表第 3 欄。如果有人在 customers 表第 2、3 欄中間插了一欄，所有 VLOOKUP 就全錯了，而且不會報錯，只會默默給你錯的數字。SQL JOIN 指定欄位名稱，加欄不影響結果。

## LEFT JOIN：保留找不到的列

INNER JOIN 只留「兩邊都有對應資料」的列。如果 customers 表裡有人從未下單，用 INNER JOIN 就看不到他。

LEFT JOIN 保留左表（FROM 後面那張表）的所有列，右表找不到對應的欄位就填 NULL：

```sql run
SELECT c.customer_id, c.name, o.order_id
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
LIMIT 15;
```

找出從未購買的會員：

```sql run
SELECT c.customer_id, c.name, c.email
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL
LIMIT 10;
```

> [!TIP] 給 Excel 用戶的小提示
> Excel 的 VLOOKUP 找不到時回傳 `#N/A`，你要用 `IFERROR` 包起來。LEFT JOIN 找不到時自動回傳 NULL，然後你用 `WHERE 右表欄位 IS NULL` 就能找到「找不到對應的列」。

> [!DIALECT] JOIN 的寫法
> `JOIN` 和 `INNER JOIN` 完全等價，在所有資料庫都一樣。LEFT JOIN 在所有主流資料庫的語法也相同。還有 RIGHT JOIN 和 FULL OUTER JOIN，但實務上 LEFT JOIN 佔了 9 成以上的使用場景。
