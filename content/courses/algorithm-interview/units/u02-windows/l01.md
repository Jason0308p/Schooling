## 為什麼需要兩端搜尋

票券價格已由小到大排列，想找兩張票剛好湊到預算。從最便宜和最貴的一端開始；總和太小就提高左端，太大就降低右端。

```js
function hasPair(prices, target) {
  let left = 0, right = prices.length - 1;
  while (left < right) {
    const sum = prices[left] + prices[right];
    if (sum === target) return true;
    if (sum < target) left++;
    else right--;
  }
  return false;
}
```

## 手跑與不變量

`[2,4,7,11]`、目標 15：先試 2+11=13，左端移至 4；4+11=15。**不變量**：已排除的端點不可能與剩餘元素湊成目標。因已排序，總和太小時固定左端、縮小右端只會更小。

## 複雜度與取捨

已排序時 O(n) 時間、O(1) 額外空間；未排序不能直接套用排除規則。先排序需 O(n log n)；或用 Set 平均 O(n) 時間、O(n) 空間。空陣列與單一元素都回傳 false，不能把同一筆票算兩次。

> [!WARN] 前提
> 訪談時先確認價格是否已排序、是否允許重複價格及是否可使用同一索引兩次。
