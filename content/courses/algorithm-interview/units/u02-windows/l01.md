## 兩張票剛好湊到預算，為何不必試遍所有組合？

售票系統已有**由小到大排序**的票價 `[2,4,7,11]`，要判斷是否存在兩張不同索引的票，合計剛好 `15`。`n` 是票價筆數；同價格可以出現兩次，但同一張票不能用兩遍。

最直覺的方法是對每張票，再試它後面的每張票。它不會漏解，但最壞會檢查 `n(n-1)/2` 組，時間 `O(n²)`、額外空間 `O(1)`。我們能不能利用「已排序」一次排除很多組？

## 從兩端開始：哪一邊可以安全丟掉？

先比較最便宜的 `2` 和最貴的 `11`：總和 `13 < 15`。固定 `2`，改配目前區間內任何比 `11` 更便宜的票，只會更小。因此 `2` 不可能與剩餘票配對成功，**左端可以右移**。接著 `4 + 11 = 15`，找到答案。

反過來，若兩端之和太大，固定右端最貴的票，換更貴的左端只會更大；**右端可以左移**。這個「整批排除」的理由，比背移動規則更重要。

```js
function hasPair(prices, target) {
  let left = 0, right = prices.length - 1;
  while (left < right) {
    const sum = prices[left] + prices[right];
    if (sum === target) return true;
    if (sum < target) left++;
    else right--;
  }
  return false;
}
```

- 第一步：`left=0, right=3`，比較 `2+11=13`；排除 `2`，左端右移。
- 第二步：`left=1, right=3`，比較 `4+11=15`；找到兩張不同索引的票。

**不變量**：若答案存在，在回傳 `true` 之前，尚未排除的 `[left, right]` 區間內仍有一組答案。每次移動都有排序證明作支撐；當兩端相遇時，不可能再選兩個不同索引，便回傳 `false`。

## 成本與改變前提

每輪至少縮小一格，合計最多縮小 `n` 格，所以**已排序時**為 `O(n)` 時間、`O(1)` 額外空間。若未排序，先複製並採高效比較排序的分析模型，總時間約 `O(n log n)`、至少 `O(n)` 複本空間；JavaScript `.sort()` 的實際實作成本不能視為規格保證。也可用 Set 掃描找補數：在平均常數時間查找的假設下為 `O(n)` 時間、`O(n)` 空間；必須先查再加入，避免把同一索引算兩次。

> [!WARN] 未排序不能直接套規則
> `[2,1,4]`、目標 `5`：先看兩端 `2+4=6`，右端左移；再看 `2+1=3`，左端右移便相遇，程式會回傳 `false`，但 `1+4=5` 明明存在。錯不在移動次數，而在未排序時無法證明「被排除的端點沒有答案」。

空陣列與單筆輸入都回傳 `false`；`[4,4]` 與目標 `8` 則可成功，因為有兩個不同索引。負數不會破壞排除證明，**排序前提**才是關鍵。
