## Format 和 Context：輸出格式和背景資訊

上一課我們學了 Role 和 Task。這一課補完後兩個維度：**Format（格式）** 和 **Context（背景）**。

四個維度合在一起，就是讓 Prompt 從「可能有用」變成「幾乎每次都有用」的關鍵。

---

## 第三個維度：Format（輸出格式）

### 為什麼要指定格式？

AI 很聰明，但它不知道你的輸出要貼到哪裡用。同樣的內容，輸出成一大段文字和輸出成條列表格，對你的工作效率影響天差地別。

**沒有 Format：**
```
分析一下我們這款 App 的優勢和劣勢。
```
→ AI 可能輸出 300 字的文章，你要手動提取重點

**加上 Format：**
```
分析我們這款 App 的優勢和劣勢，用 Markdown 表格呈現，欄位：面向 | 優勢 | 劣勢 | 改進建議。
每個欄位用 1-2 句話，不要超過 15 字。
```
→ AI 直接輸出可貼進 Notion 的表格

### 常用格式指令對照表

| 用途 | Format 指令 |
|------|------------|
| **簡報投影片** | 「用條列式，每點不超過 15 字，最多 5 點」 |
| **報告或 PRD** | 「用 Markdown 格式，## 為大標題，每節 150-200 字」 |
| **資料處理** | 「輸出 JSON 陣列，每個物件包含 title、summary、priority 三個 key」 |
| **對照分析** | 「用表格整理，欄位為 A、B、C，不需要額外說明文字」 |
| **Email / 文案** | 「分三段：開場（1 句）→ 主體（3 句）→ 行動呼籲（1 句）」 |
| **程式碼** | 「只輸出程式碼，不要加解釋，使用 TypeScript」 |

### 長度控制

字數和長度是最常被忽略的 Format 設定：

```
# 太長的版本（沒有限制）
解釋什麼是 A/B 測試。

# 有長度控制的版本
用 3 句話解釋什麼是 A/B 測試，對象是沒有技術背景的行銷主管。
```

> [!TIP] 實務技巧
> 給範圍而不是死板數字：「100-150 字」比「剛好 120 字」更自然，AI 也更容易遵守。

## 第四個維度：Context（背景資訊）

### 什麼是有效的 Context？

Context 是「只有你知道、但 AI 需要知道才能給出好答案」的背景資訊。

它回答四個問題：
1. **誰**在用這個輸出？（目標受眾）
2. **在哪裡**用？（用途和平台）
3. **已知什麼**？（現有情況）
4. **不能做什麼**？（限制和邊界）

### Context 好壞對比

**任務：寫一封活動邀請信**

```
# 沒有 Context
寫一封活動邀請信。

# 有 Context
背景：
- 活動：線下行銷人脈交流會，免費參加
- 日期：11/15（五）晚上 7 點，台北信義區
- 收件人：曾經購買過我們課程的行銷人，年齡大多 25-35 歲
- 目的：讓他們報名參加，並在活動中分享課程心得
- 限制：不要用「恭喜您獲得邀請」這類浮誇開頭
```

有了 Context，AI 知道語氣要輕鬆（非正式活動）、要強調免費和地點方便性，並且避免你不喜歡的用詞。

### 哪些 Context 最有價值？

並非所有 Context 都同等重要。以下是**影響最大**的幾類：

**1. 目標受眾特徵**
```
讀者是台灣中小企業的老闆，平均年齡 45 歲，不熟悉 SaaS 術語。
```

**2. 輸出的用途**
```
這份文案要放在 Google 廣告的描述欄位，最多 90 個字元。
```

**3. 現有情況或限制**
```
客戶上個月才抱怨過類似問題，這封信需要特別謹慎處理。
我們沒有預算提供退款，只能提供替代方案。
```

**4. 不要做什麼**
```
不要使用「業界領先」「一站式解決方案」這類過度行銷的用語。
不要自行補充數據，只根據我提供的資料回答。
```

> [!WARN] 常見錯誤
> Context 太多不一定好。提供 5 個真正相關的 Context，比提供 20 個其中只有 3 個有用的 Context 效果更好。選最影響輸出的背景資訊。

## 四個維度完整範例

讓我們用一個完整的例子把四個維度組合起來：

**任務：幫產品部門寫季度回顧摘要**

```
【Role】
你是一位有 5 年經驗的產品經理，習慣用數據說話，簡報風格直接不廢話。

【Task】
根據以下資料，寫一份 Q3 產品進度季度回顧摘要：
- 完成功能：智慧搜尋（9 月上線）、批次匯出功能（8 月上線）
- 延遲功能：用戶通知中心（預計 Q4 完成）
- 關鍵指標：MAU 成長 12%、NPS 從 32 提升至 41

【Format】
用 Markdown 格式，結構：
## 本季亮點（3 點條列，每點不超過 20 字）
## 延遲項目說明（1 段，說明原因和下一步）
## Q4 優先事項（2 點）

【Context】
受眾是 C-level 主管，每季度都很忙，只看 2 分鐘。
語氣直接、積極，不要為延遲過度道歉，聚焦在下一步。
```

> [!BIZ] 為什麼這個框架在工作中很有用
> 四個維度框架最大的好處是：**可以複用**。一旦你為某個場景建立了模板，下次只需要替換數據和 Context，Role、Task、Format 的結構保持不變，節省大量時間。

---

## 小結：四個維度一覽

| 維度 | 核心問題 | 沒有它的後果 |
|------|----------|------------|
| **Role** | AI 以誰的視角回答？ | 輸出太泛用、缺乏專業深度 |
| **Task** | AI 具體要做什麼？ | 輸出不符合需求、需要反覆修改 |
| **Format** | 輸出長什麼樣？ | 輸出不能直接使用，要手動整理 |
| **Context** | AI 需要知道什麼背景？ | 輸出忽略了重要限制或特殊情況 |

下一單元，我們來看**常見錯誤**——為什麼有時候就算用了框架，AI 還是輸出了一堆廢話。
