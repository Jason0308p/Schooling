## 高難度面試題：能不能想清楚再動手？

這一組是 Lead / Senior 職缺，或頂尖公司分析師職缺的筆試難題。這層不只是「語法對不對」，而是**你對 SQL 執行邏輯的理解有多深**。

## 這層面試的特點

- 題目本身不難理解，但 SQL 的實作路徑不只一條
- 考驗你能不能想清楚「邊界條件」，例如：連續日期的判斷、多期間對比的 pivot
- 面試官常在你寫完後說「改一下需求」，測試你對自己 SQL 的掌控度
- 時間壓力下，能不能把複雜問題拆成多個可驗證的步驟

## 答題建議思路

高難題的標準流程：

1. **先說思路，再寫 SQL**：高難題的評分有一部分是「你能不能說清楚自己要做什麼」
2. **先寫 CTE，再組合**：不要一開始就寫一個大 SQL，先把每一步的中間結果想清楚
3. **想清楚邊界條件**：「連續 3 天」是指哪種連續？「最近 30 天」是 >= -30 days 還是 > -30 days？
4. **自己驗算一個例子**：連續日期題可以在腦中走一個 3 天的範例，確認邏輯正確

> [!TIP] 面試小技巧
> 遇到連續日期類的問題，先把「差一步」的中間結果說出來：「我先算每個顧客有訂單的日期，再用 ROW_NUMBER 減日期的方式找出連續組。」說出來讓面試官知道你有思路，就算 SQL 有語法錯誤也是加分。

> [!BIZ] 為什麼面試官出這種題
> 連續日期、多期間對比、PARTITION BY 取前 N 是真實工作裡每週都會遇到的需求，但能靠自己寫出來的人很少。這種題直接過濾掉只會「複製貼上」的候選人。

## 常見扣分點

### 連續日期相關
- 用 `LEAD/LAG` 比較相鄰日期（只能找「相差 1 天」，找不到「連續 N 天」的區間）
- `ROW_NUMBER` 相減法的邏輯沒說清楚（為什麼用日期 - ROW_NUMBER？）
- 沒有先 DISTINCT 日期就直接用 ROW_NUMBER（同一天有多筆訂單會讓 row number 跳）

### 多期間對比相關
- 用多個子查詢分別算，但沒有說明能不能用 UNION 或 CASE WHEN 合成單一查詢
- 時間範圍計算錯誤（最近 30 天的分母 vs 最近 60 天的分母要各自獨立）

### PARTITION BY 取前 N 相關
- 忘記用 CTE 或子查詢包裝 window function，直接在 WHERE 用
- RANK vs ROW_NUMBER vs DENSE_RANK 的差異不清楚（同分怎麼處理？）

## 追問方向

- 「連續日期題改成連續 5 天怎麼修？」（只改 HAVING 的條件）
- 「PARTITION BY 取前 N 的題，如果有同名次（同分），你要取幾個？」
- 「多期間對比的 SQL，如果要加第四個期間（120 天），你怎麼改？」
