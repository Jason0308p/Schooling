# Day 1 / Day 7 / Day 30 留存率

## 什麼是留存率？

留存率衡量「某天加入的用戶，在 N 天後還有多少人繼續使用」。

```
Day N 留存率 = 在第 N 天（±容差）還活躍的用戶數 ÷ 原始用戶數 × 100%
```

## 業界參考值

| 指標 | 優秀 | 普通 | 需改善 |
|------|------|------|--------|
| Day 1 留存 | > 40% | 25–40% | < 25% |
| Day 7 留存 | > 25% | 15–25% | < 15% |
| Day 30 留存 | > 15% | 8–15% | < 8% |

## SQLite 計算天數差

SQLite 沒有 `DATEDIFF`，用 `julianday` 替代：

```sql
-- 計算兩個日期相差幾天
SELECT julianday('2025-03-10') - julianday('2025-03-01');  -- 結果：9
```

## Day 7 留存範例

```sql
SELECT
  COUNT(DISTINCT u.user_id)  AS total_users,
  COUNT(DISTINCT da.user_id) AS retained_d7,
  ROUND(COUNT(DISTINCT da.user_id) * 100.0
        / COUNT(DISTINCT u.user_id), 2) AS d7_pct
FROM users u
LEFT JOIN daily_active da
  ON  da.user_id = u.user_id
  AND julianday(da.log_date) - julianday(u.signup_date) BETWEEN 6 AND 8;
```

## 為什麼用 LEFT JOIN？

如果用 INNER JOIN，沒有留存的用戶不會出現，分母就只有「有留存的用戶」，留存率會變成 100%——這是最常見的錯誤！
