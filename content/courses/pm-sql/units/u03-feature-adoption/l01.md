# 計算功能採用率（Feature Adoption Rate）

## 什麼是功能採用率？

```
功能採用率 = 使用過該功能的不重複用戶數 ÷ 活躍用戶總數 × 100%
```

## 採用率 vs 使用頻率

| 指標 | 公式 | 衡量什麼 |
|------|------|---------|
| 採用率（Adoption Rate）| 用過的用戶數 / 活躍用戶數 | 有多少人「知道並用過」這個功能 |
| 使用頻率（Usage Frequency）| 總使用次數 / 使用用戶數 | 使用者的平均使用深度 |

## 功能事件漏斗

```
viewed → used → completed
```

- **viewed**：用戶看到了這個功能（例如進入功能頁面）
- **used**：用戶執行了這個功能
- **completed**：用戶完成了完整的功能流程

## 計算範例

```sql
-- 各功能採用率（分母 = 所有活躍用戶）
WITH active_base AS (
  SELECT COUNT(*) AS total FROM users WHERE is_active = 1
)
SELECT
  feature_name,
  COUNT(DISTINCT user_id) AS unique_users,
  ROUND(COUNT(DISTINCT user_id) * 100.0
        / (SELECT total FROM active_base), 2) AS adoption_pct
FROM feature_events
GROUP BY feature_name
ORDER BY adoption_pct DESC;
```

## 低採用率的可能原因

1. **功能藏太深**（可發現性問題）→ 改 UI 入口
2. **功能本身不吸引人**（價值問題）→ 重新設計
3. **功能只適合特定用戶**（目標受眾問題）→ 針對特定群體推廣
