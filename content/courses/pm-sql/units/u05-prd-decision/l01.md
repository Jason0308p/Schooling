# 用數據支撐產品決策

## 數據驅動決策的流程

```
業務問題 → 指標選擇 → SQL 查詢 → 數據解讀 → 行動建議
```

## PM 常見的決策情境

### 情境 1：要不要做這個功能？
- 查：目標用戶的需求強度（功能採用率）
- 查：使用了該功能的用戶，留存率是否更高（相關性）
- 建議：先做 A/B Test 驗證因果

### 情境 2：這個實驗要不要推廣？
- 查：轉換率 Lift 是否顯著（Z-score > 1.96）
- 查：ARPU 是否提升（防止低價轉換）
- 建議：顯著 + ARPU 提升 → 推廣；僅轉換率提升但 ARPU 下降 → 需要更多分析

### 情境 3：要優先服務哪個用戶群？
- 查：高黏性用戶的特徵（plan、country、功能使用）
- 查：高留存用戶的共同行為
- 建議：建立 ICP（Ideal Customer Profile）

## 數據的局限性

| 數據能做到 | 數據無法做到 |
|-----------|-------------|
| 描述現象（用戶在做什麼）| 解釋動機（用戶為什麼這樣做） |
| 驗證假設（A/B Test） | 提出假設（需要用戶研究） |
| 發現相關性 | 直接證明因果 |

## 寫 PRD 時如何引用數據

❌ 「我們認為推廣 report 功能可以提升留存」

✅ 「數據顯示，使用過 report 功能的用戶 Day 30 留存率為 XX%，比未使用者高出 YY 個百分點（基於 N=XXX 的觀察）。我們計劃通過 A/B Test 驗證引導使用 report 功能是否可以因果性地提升留存。」
