## Rolling Retention vs Bracket Retention

## Growth 視角：用對留存定義，避免誤判產品健康度

不同的留存定義會給出截然不同的數字，如果沒有統一定義，跨團隊的數字就無法比較。
這堂課深入比較 **Rolling retention** 和 **Bracket retention**（區間留存），讓你能選對工具。

## 什麼是 Bracket Retention？

Bracket retention 把時間切成幾個「區間桶」，只要用戶在該區間內有活躍就算留存。

| 類型 | 定義 |
|------|------|
| N-day retention | 第 N 天（±容差）有活躍 |
| Rolling retention | 第 N 天**之後任何一天**有活躍 |
| Bracket retention | 在某個**時間區間**（例如第 8–14 天）有活躍 |

```sql run
-- Bracket retention：Week 1（1-7天）、Week 2（8-14天）、Week 4（22-28天）
WITH brackets AS (
  SELECT
    u.user_id,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 1  AND 7  THEN 1 ELSE 0 END) AS w1,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 8  AND 14 THEN 1 ELSE 0 END) AS w2,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 22 AND 28 THEN 1 ELSE 0 END) AS w4
  FROM users u
  LEFT JOIN daily_active da ON da.user_id = u.user_id
  GROUP BY u.user_id
)
SELECT
  COUNT(*)                              AS total_users,
  ROUND(SUM(w1) * 100.0 / COUNT(*), 1) AS w1_pct,
  ROUND(SUM(w2) * 100.0 / COUNT(*), 1) AS w2_pct,
  ROUND(SUM(w4) * 100.0 / COUNT(*), 1) AS w4_pct
FROM brackets;
```

> [!BIZ] 業務決策意義
> Bracket retention 比 N-day 更適合衡量**週期性產品**（例如每週用一次的報表工具）。
> W1→W2 的衰減代表「第一週熱情期之後」是否還有人回來，是判斷核心黏性的關鍵。

## Cohort 留存：按月份分群比較

```sql run
-- 2025-01 ~ 2025-06 各 Cohort 的 W1 留存率
WITH cohort_flags AS (
  SELECT
    strftime('%Y-%m', u.signup_date) AS cohort_month,
    u.user_id,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 1 AND 7
             THEN 1 ELSE 0 END) AS w1
  FROM users u
  LEFT JOIN daily_active da ON da.user_id = u.user_id
  WHERE u.signup_date BETWEEN '2025-01-01' AND '2025-06-30'
  GROUP BY u.user_id, cohort_month
)
SELECT
  cohort_month,
  COUNT(*)                              AS cohort_size,
  SUM(w1)                               AS w1_retained,
  ROUND(SUM(w1) * 100.0 / COUNT(*), 1) AS w1_pct
FROM cohort_flags
GROUP BY cohort_month
ORDER BY cohort_month;
```

## 留存衰減速度分析

```sql run
-- 比較各方案（free/pro/enterprise）的 W1 vs W4 留存率衰減
WITH brackets AS (
  SELECT
    u.user_id,
    u.plan,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 1  AND 7  THEN 1 ELSE 0 END) AS w1,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 22 AND 28 THEN 1 ELSE 0 END) AS w4
  FROM users u
  LEFT JOIN daily_active da ON da.user_id = u.user_id
  GROUP BY u.user_id, u.plan
)
SELECT
  plan,
  COUNT(*)                              AS total_users,
  ROUND(SUM(w1) * 100.0 / COUNT(*), 1) AS w1_pct,
  ROUND(SUM(w4) * 100.0 / COUNT(*), 1) AS w4_pct,
  ROUND((SUM(w1) - SUM(w4)) * 100.0 / NULLIF(SUM(w1), 0), 1) AS w1_to_w4_drop_pct
FROM brackets
GROUP BY plan
ORDER BY w4_pct DESC;
```

> [!TIP] 常見陷阱：Rolling retention 永遠不會下降
> Rolling retention 定義是「第 N 天**或之後**有活躍」——時間越往後，留存率只能持平或更高，
> 因此 Rolling D30 ≥ Rolling D7 是必然的，這條曲線沒有下降趨勢，無法用來判斷流失點。

> [!DIALECT] BigQuery / Mixpanel 對應做法
> **BigQuery：** 用 `DATE_DIFF` 加 `BETWEEN` 區間，邏輯相同。
> **Mixpanel：** Retention 報表選「Bracket」模式，直接設定觀察區間。
> **Amplitude：** Return On 模式（任意事件回訪）= Rolling retention；Return On（指定區間）= Bracket retention。
