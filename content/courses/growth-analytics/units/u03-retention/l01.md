## N-Day Retention：留存率的基礎定義

## Growth 視角：留存是增長的地基

所有增長指標中，**留存率**是最重要的一個。獲客再多，留不住就是在漏水桶裡倒水。
N-day retention 是最直接的衡量方式：「第 N 天，有多少用戶還在？」

## N-Day vs Rolling Retention：兩種定義

| 定義 | 計算方式 | 特性 |
|------|----------|------|
| **N-day retention** | 第 N 天（±容差）有活躍 | 單點快照，容易計算 |
| **Rolling retention** | 第 N 天**或之後**任何一天有活躍 | 較寬鬆，適合低頻產品 |

```sql run
-- Day 7 retention（N-day 定義，±1 天容差）
SELECT
  COUNT(DISTINCT u.user_id)                             AS total_users,
  COUNT(DISTINCT da.user_id)                            AS retained_d7,
  ROUND(COUNT(DISTINCT da.user_id) * 100.0
        / COUNT(DISTINCT u.user_id), 2)                 AS d7_retention_pct
FROM users u
LEFT JOIN daily_active da
  ON  da.user_id = u.user_id
  AND julianday(da.log_date) - julianday(u.signup_date) BETWEEN 6 AND 8;
```

> [!BIZ] 業務決策意義
> Day 7 留存是衡量「新手引導是否成功」的關鍵指標。
> 若 Day 7 < 15%，代表大部分用戶在第一週就流失，Onboarding 需要立即優化。

## Day 7 vs Day 30：同時計算

```sql run
-- 一次計算 D7 和 D30 留存率
WITH flags AS (
  SELECT
    u.user_id,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 6  AND 8  THEN 1 ELSE 0 END) AS d7,
    MAX(CASE WHEN julianday(da.log_date)-julianday(u.signup_date) BETWEEN 28 AND 32 THEN 1 ELSE 0 END) AS d30
  FROM users u
  LEFT JOIN daily_active da ON da.user_id = u.user_id
  GROUP BY u.user_id
)
SELECT
  COUNT(*)                              AS total_users,
  ROUND(SUM(d7)  * 100.0 / COUNT(*), 2) AS d7_pct,
  ROUND(SUM(d30) * 100.0 / COUNT(*), 2) AS d30_pct
FROM flags;
```

## Rolling Retention 概念示範

```sql run
-- Rolling Day 7 retention：signup 後 7 天內（含第 7 天）有任何一次活躍
SELECT
  COUNT(DISTINCT u.user_id)                             AS total_users,
  COUNT(DISTINCT da.user_id)                            AS rolling_d7_retained,
  ROUND(COUNT(DISTINCT da.user_id) * 100.0
        / COUNT(DISTINCT u.user_id), 2)                 AS rolling_d7_pct
FROM users u
LEFT JOIN daily_active da
  ON  da.user_id = u.user_id
  AND julianday(da.log_date) - julianday(u.signup_date) BETWEEN 1 AND 7;
```

> [!TIP] N-day vs Rolling Retention 的差異
> - **N-day retention** 數字通常較低（只看特定那天），適合高頻 App（每天用）
> - **Rolling retention** 較高（7 天內任何一天都算），適合低頻工具（每週用幾次）
> - 同一份數據，Rolling D7 幾乎必定高於 N-day D7——兩個數字不要混著比較！

> [!DIALECT] BigQuery / Mixpanel 對應做法
> **BigQuery：** `DATE_DIFF(log_date, signup_date, DAY)` 替換 `julianday` 差值。
> **Mixpanel：** Retention 報表內建 N-day 和 Unbounded（Rolling）模式切換。
> **Amplitude：** N-Day Retention 報表可直接設定觀察天數與容差。
