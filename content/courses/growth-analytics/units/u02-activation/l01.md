## Activation 啟動分析

## Growth 視角：用戶「活了」才算 Acquisition 成功

獲客只是第一步——用戶下載了 App、卻從未真正使用核心功能，等同於沒有獲客。
**Activation** 衡量用戶第一次體驗到產品核心價值的速度（Time-to-value）與比例（Onboarding 完成率）。

## 什麼是 Time-to-value（TTV）？

TTV = 從註冊到**第一次使用核心功能**的天數。
核心功能通常是產品的 Aha Moment——對 AppFlow 而言，`dashboard` 是最關鍵的第一個功能。

```sql run
-- 計算每位用戶的 Time-to-value（從 signup 到第一次用 dashboard 的天數）
SELECT
  u.user_id,
  u.signup_date,
  MIN(fe.event_date)                                           AS first_dashboard_date,
  CAST(julianday(MIN(fe.event_date)) - julianday(u.signup_date) AS INTEGER) AS days_to_value
FROM users u
JOIN feature_events fe
  ON  fe.user_id = u.user_id
  AND fe.feature_name = 'dashboard'
GROUP BY u.user_id, u.signup_date
ORDER BY days_to_value
LIMIT 20;
```

> [!BIZ] 業務決策意義
> TTV 越短，用戶越快感受到產品價值，留存率通常越高。
> 如果大部分用戶 TTV > 7 天，代表 Onboarding 流程有問題——要麼引導不夠，要麼功能太難找。

## Activation Rate：有多少用戶完成啟動？

```sql run
-- Activation rate：曾用過 dashboard 的用戶 / 總用戶數
SELECT
  COUNT(DISTINCT u.user_id)                                    AS total_users,
  COUNT(DISTINCT fe.user_id)                                   AS activated_users,
  ROUND(COUNT(DISTINCT fe.user_id) * 100.0
        / COUNT(DISTINCT u.user_id), 1)                        AS activation_rate_pct
FROM users u
LEFT JOIN feature_events fe
  ON  fe.user_id = u.user_id
  AND fe.feature_name = 'dashboard';
```

## TTV 分布：快 vs 慢啟動用戶

```sql run
-- TTV 分組：0天（當天）、1-3天、4-7天、7天以上、從未啟動
WITH ttv AS (
  SELECT
    u.user_id,
    MIN(CAST(julianday(fe.event_date) - julianday(u.signup_date) AS INTEGER)) AS days_to_value
  FROM users u
  LEFT JOIN feature_events fe
    ON  fe.user_id = u.user_id
    AND fe.feature_name = 'dashboard'
  GROUP BY u.user_id
)
SELECT
  CASE
    WHEN days_to_value IS NULL  THEN '從未啟動'
    WHEN days_to_value = 0      THEN '當天（Day 0）'
    WHEN days_to_value <= 3     THEN 'Day 1–3'
    WHEN days_to_value <= 7     THEN 'Day 4–7'
    ELSE 'Day 8+'
  END                          AS ttv_bucket,
  COUNT(*)                     AS users,
  ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM users), 1) AS pct
FROM ttv
GROUP BY ttv_bucket
ORDER BY
  CASE ttv_bucket
    WHEN '當天（Day 0）' THEN 1
    WHEN 'Day 1–3'      THEN 2
    WHEN 'Day 4–7'      THEN 3
    WHEN 'Day 8+'       THEN 4
    ELSE 5
  END;
```

> [!TIP] 常見陷阱：Activation 定義因產品而異
> 「啟動」沒有統一標準——有些產品定義為「完成第一次核心操作」，有些是「第一次邀請隊友」。
> 重要的是：選的 Activation 事件要和長期留存有高相關性（可以跑相關性分析驗證）。

```sql run
-- 各渠道的 Activation rate 比較
SELECT
  u.acquisition_channel,
  COUNT(DISTINCT u.user_id)                                    AS total_users,
  COUNT(DISTINCT fe.user_id)                                   AS activated_users,
  ROUND(COUNT(DISTINCT fe.user_id) * 100.0
        / COUNT(DISTINCT u.user_id), 1)                        AS activation_rate_pct
FROM users u
LEFT JOIN feature_events fe
  ON  fe.user_id = u.user_id
  AND fe.feature_name = 'dashboard'
GROUP BY u.acquisition_channel
ORDER BY activation_rate_pct DESC;
```

> [!DIALECT] BigQuery / Amplitude 對應做法
> **BigQuery：** `DATE_DIFF(first_event_date, signup_date, DAY)` 直接算天數差。
> **Amplitude：** 在 Funnel 分析選「Registration → Dashboard Viewed」，可直接看 conversion rate 和 time-to-convert。
> **Mixpanel：** Funnels 報表同理，還可以設定 conversion window（例如 7 天內）。
