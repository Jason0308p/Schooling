## Acquisition 獲客分析

## Growth 視角：為什麼「渠道品質」比「渠道數量」更重要

用戶數增長很容易用廣告買到，但如果買來的用戶三天後就流失，CAC（客戶獲取成本）就是浪費。
Growth 團隊的核心任務是找到「又便宜、留存又好」的渠道——用 SQL 把數據說話。

```sql run
-- 各渠道用戶總數概覽
SELECT
  acquisition_channel,
  COUNT(*)                              AS total_users,
  ROUND(COUNT(*) * 100.0
        / (SELECT COUNT(*) FROM users), 1) AS pct
FROM users
GROUP BY acquisition_channel
ORDER BY total_users DESC;
```

> [!BIZ] 業務決策意義
> 光看用戶數不夠——渠道帶來的用戶品質（留存率、付費率）才是 Growth 真正在意的。
> 一個渠道帶來 1000 人但 95% 流失，遠不如帶來 200 人但 60% 留存的渠道。

## 渠道品質：活躍率

```sql run
-- 各渠道的活躍用戶比例（is_active = 1）
SELECT
  acquisition_channel,
  COUNT(*)                                            AS total_users,
  SUM(is_active)                                      AS active_users,
  ROUND(SUM(is_active) * 100.0 / COUNT(*), 1)        AS active_rate_pct
FROM users
GROUP BY acquisition_channel
ORDER BY active_rate_pct DESC;
```

## 渠道品質：付費轉換率

```sql run
-- 各渠道的 Pro/Enterprise 付費用戶比例
SELECT
  acquisition_channel,
  COUNT(*)                                                         AS total_users,
  SUM(CASE WHEN plan IN ('pro', 'enterprise') THEN 1 ELSE 0 END)  AS paid_users,
  ROUND(
    SUM(CASE WHEN plan IN ('pro', 'enterprise') THEN 1 ELSE 0 END)
    * 100.0 / COUNT(*), 1
  )                                                                AS paid_pct
FROM users
GROUP BY acquisition_channel
ORDER BY paid_pct DESC;
```

> [!TIP] 常見陷阱：忘記控制 Cohort 時間
> 不同渠道的用戶加入時間可能不同（例如：paid_search 是最近才大量投放），
> 較新加入的用戶自然活躍率較低，不一定代表渠道品質差。
> 精準分析應控制「同期加入的用戶」（Cohort 分析），才能做公平比較。

## 各渠道平台分布

```sql run
-- 各渠道用戶的平台偏好
SELECT
  acquisition_channel,
  platform,
  COUNT(*) AS users
FROM users
GROUP BY acquisition_channel, platform
ORDER BY acquisition_channel, users DESC;
```

> [!DIALECT] BigQuery / Mixpanel 對應做法
> **BigQuery：** 把 `julianday` 換成 `DATE_DIFF(date1, date2, DAY)`；渠道分析通常直接 JOIN utm 參數表。
> **Mixpanel：** 在 Insights 報表選「分群」→「Initial UTM Source」可直接比較各來源的留存率，不需寫 SQL。
> **GA4：** `SELECT event_params` 搭配 UNNEST 取 `session_default_channel_group`，效果類似。
