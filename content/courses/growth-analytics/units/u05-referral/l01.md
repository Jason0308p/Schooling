## A/B Test 分析與 Referral 機制

## Growth 視角：A/B Test 是 Growth 的科學方法

沒有 A/B Test，Growth 靠的是直覺；有了 A/B Test，每次改版都有數據支撐。
這堂課學習：用 SQL 計算 A/B Test 轉換率、收入提升，以及如何判斷結果是否值得信賴。

## A/B Test 基本結果：轉換率比較

```sql run
-- 各實驗的 Control vs Treatment 轉換率比較
SELECT
  test_name,
  variant,
  COUNT(*)                                             AS users,
  SUM(converted)                                       AS conversions,
  ROUND(SUM(converted) * 100.0 / COUNT(*), 2)         AS cvr_pct,
  ROUND(SUM(revenue), 2)                               AS total_revenue,
  ROUND(AVG(revenue), 2)                               AS arpu
FROM ab_tests
GROUP BY test_name, variant
ORDER BY test_name, variant;
```

> [!BIZ] 業務決策意義
> 轉換率提升 1% 在規模化後可能帶來數百萬元的額外收入。
> 但別只看轉換率——`arpu`（每用戶平均收入）才是真正的 North Star：
> 有可能 Treatment 轉換率高，但轉換金額低，導致總收入不如 Control。

## 計算 Lift（提升幅度）

```sql run
-- 計算各實驗的轉換率 Lift（treatment vs control 的相對提升）
WITH stats AS (
  SELECT
    test_name,
    variant,
    COUNT(*) AS n,
    SUM(converted) AS conv,
    ROUND(SUM(converted) * 100.0 / COUNT(*), 4) AS cvr
  FROM ab_tests
  GROUP BY test_name, variant
)
SELECT
  c.test_name,
  ROUND(c.cvr, 2)                                     AS control_cvr_pct,
  ROUND(t.cvr, 2)                                     AS treatment_cvr_pct,
  ROUND((t.cvr - c.cvr), 2)                           AS absolute_lift_pct,
  ROUND((t.cvr - c.cvr) / NULLIF(c.cvr, 0) * 100, 1) AS relative_lift_pct
FROM stats c
JOIN stats t ON t.test_name = c.test_name AND t.variant = 'treatment'
WHERE c.variant = 'control'
ORDER BY relative_lift_pct DESC;
```

> [!TIP] 統計顯著性的陷阱
> SQL 可以算 Lift，但**不能**直接判斷統計顯著性（p-value）。
> 實務做法：用 Python `scipy.stats.proportions_ztest` 或線上計算機（如 Evan Miller A/B Calculator）。
> 樣本數少（< 100/組）時，任何 Lift 都可能是隨機波動，不要就此做出產品決策。

## Revenue Lift：收入角度的分析

```sql run
-- 各實驗 Treatment 帶來的收入提升（vs Control）
WITH rev AS (
  SELECT
    test_name,
    variant,
    COUNT(*) AS n,
    ROUND(SUM(revenue), 2) AS total_rev,
    ROUND(AVG(revenue), 4) AS arpu
  FROM ab_tests
  GROUP BY test_name, variant
)
SELECT
  c.test_name,
  ROUND(c.arpu, 2)                              AS control_arpu,
  ROUND(t.arpu, 2)                              AS treatment_arpu,
  ROUND(t.arpu - c.arpu, 2)                     AS arpu_lift,
  ROUND((t.arpu - c.arpu) / NULLIF(c.arpu, 0) * 100, 1) AS arpu_lift_pct
FROM rev c
JOIN rev t ON t.test_name = c.test_name AND t.variant = 'treatment'
WHERE c.variant = 'control'
ORDER BY arpu_lift DESC;
```

## Viral Coefficient 概念

Viral coefficient（K factor）= 平均每位用戶帶來的新用戶數。
K > 1 代表病毒式增長（不常見）；K = 0.5 代表每 2 位用戶帶來 1 位新用戶。

```sql run
-- 估算 referral 渠道的病毒係數（referral 用戶數 / 介紹者估算）
SELECT
  acquisition_channel,
  COUNT(*) AS users,
  ROUND(COUNT(*) * 1.0 / (SELECT COUNT(*) FROM users WHERE acquisition_channel = 'referral'), 3) AS share_of_referral
FROM users
WHERE acquisition_channel = 'referral'
GROUP BY acquisition_channel;
```
