## GA4 歸因分析：UTM 參數與多通路歸因

**歸因（Attribution）** 回答的問題是：「這筆訂單，到底是哪個行銷管道帶來的？」

GA4 用 UTM 參數來記錄流量來源，再透過 session ID 把行為（events）和後續的訂單串起來。

## UTM 參數是什麼？

UTM 是 Urchin Tracking Module 的縮寫，是廣告連結後面加的追蹤參數：

```
https://example.com/products/tumbler
  ?utm_source=google
  &utm_medium=cpc
  &utm_campaign=tumbler-shopping-2025
```

| UTM 參數 | 資料集欄位 | 意義 | 範例 |
|---|---|---|---|
| utm_source | `source` | 流量來源 | google, facebook |
| utm_medium | `medium` | 媒介類型 | cpc, organic, email |
| utm_campaign | `campaign_id` | 具體活動 | 關鍵字廣告、聖誕禮物再行銷 |

## 查看各來源流量

```sql run
SELECT
  source,
  medium,
  COUNT(DISTINCT session_id) AS sessions,
  COUNT(DISTINCT customer_id) AS logged_in_users
FROM sessions
GROUP BY source, medium
ORDER BY sessions DESC;
```

## Sessions 如何連接訂單？

歸因的串接路徑：

```
sessions.campaign_id  ←  廣告活動
sessions.customer_id  →  orders.customer_id（同一個人）
sessions.session_start ≤  orders.order_date  （先看廣告，後下單）
```

```sql run
SELECT
  s.campaign_id,
  COUNT(DISTINCT o.order_id) AS attributed_orders,
  ROUND(SUM(o.total_amount)) AS attributed_revenue
FROM sessions s
JOIN orders o
  ON  o.customer_id = s.customer_id
  AND o.order_date >= DATE(s.session_start)
  AND o.status = 'completed'
WHERE s.campaign_id IS NOT NULL
GROUP BY s.campaign_id
HAVING COUNT(DISTINCT o.order_id) > 0
ORDER BY attributed_revenue DESC;
```

> [!BIZ] **為什麼要加 order_date >= session_start？**
>
> 沒有這個條件，訂單可能是比廣告曝光更早就存在的，那就不算是廣告帶來的轉換。
> 加了這個條件，才是真正的「廣告點擊 → 後續購買」歸因邏輯。

## 串聯廣告名稱與花費

```sql run
WITH attr AS (
  SELECT
    s.campaign_id,
    COUNT(DISTINCT o.order_id) AS attributed_orders,
    ROUND(SUM(o.total_amount)) AS attributed_revenue
  FROM sessions s
  JOIN orders o
    ON  o.customer_id = s.customer_id
    AND o.order_date >= DATE(s.session_start)
    AND o.status = 'completed'
  WHERE s.campaign_id IS NOT NULL
  GROUP BY s.campaign_id
),
spend AS (
  SELECT campaign_id, ROUND(SUM(cost)) AS total_cost
  FROM ad_spend
  GROUP BY campaign_id
)
SELECT
  c.campaign_name,
  c.platform,
  sp.total_cost,
  COALESCE(a.attributed_revenue, 0) AS attributed_revenue,
  ROUND(COALESCE(a.attributed_revenue, 0) / NULLIF(sp.total_cost, 0), 2) AS roas
FROM campaigns c
LEFT JOIN attr a ON c.campaign_id = a.campaign_id
LEFT JOIN spend sp ON c.campaign_id = sp.campaign_id
ORDER BY roas DESC NULLS LAST;
```

> [!DIALECT] **BigQuery GA4：如何做歸因**
>
> BigQuery GA4 本身不直接記錄訂單，通常需要把 GA4 的 session 資料和 CRM/訂單系統的資料 JOIN。
>
> 串接方法一（有 user_id）：
> ```sql
> SELECT
>   ga.session_source,
>   COUNT(DISTINCT crm.order_id) AS attributed_orders
> FROM ga4_sessions ga
> JOIN crm_orders crm
>   ON ga.user_id = crm.customer_id
>   AND crm.order_date >= ga.session_date
> GROUP BY ga.session_source
> ```
>
> 方法二（用 client_id cookie 匹配，準確率較低但涵蓋未登入訪客）。
>
> GA4 後台的「轉換歸因」報表是 Google 用自家演算法（Data-Driven Attribution）計算的，與手動 SQL 的「最後點擊」歸因結果不會完全相同。

## 按來源計算購買率

```sql run
WITH all_s AS (
  SELECT source, COUNT(DISTINCT session_id) AS sessions
  FROM sessions
  GROUP BY source
),
pur_s AS (
  SELECT s.source, COUNT(DISTINCT e.session_id) AS purchase_sessions
  FROM events e
  JOIN sessions s ON e.session_id = s.session_id
  WHERE e.event_name = 'purchase'
  GROUP BY s.source
)
SELECT
  a.source,
  a.sessions,
  COALESCE(p.purchase_sessions, 0) AS purchase_sessions,
  ROUND(COALESCE(p.purchase_sessions, 0) * 100.0 / NULLIF(a.sessions, 0), 2) AS purchase_rate
FROM all_s a
LEFT JOIN pur_s p ON a.source = p.source
ORDER BY purchase_rate DESC;
```

> [!TIP] **歸因模型的選擇**
>
> 本課用的是「最後點擊（Last Click）」模型：訂單歸因給最後一次的廣告接觸。
>
> 實務上還有：
> - **首次點擊（First Click）**：歸因給第一次接觸
> - **線性（Linear）**：平均分配給所有接觸點
> - **數據驅動（Data-Driven）**：Google 用 ML 模型計算（GA4 付費版）
>
> 不同模型會給出不同的預算分配建議，沒有絕對正確的答案，要看業務目標。
