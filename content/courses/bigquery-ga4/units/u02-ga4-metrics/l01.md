## GA4 核心指標計算（一）：Sessions、Users、Pageviews

GA4 後台最常看的三個指標是 **Sessions（工作階段）**、**Users（使用者）**、**Pageviews（頁面瀏覽數）**。本課計算模擬資料的對應口徑，不宣稱還原後台數字。

## Sessions vs Users

在 GA4 中，一個 User 可以在不同時間開啟多個 Session。
本資料集的對應關係：

- **Sessions** = `sessions` 表的不重複 `session_id`
- **Users（已登入）** = `sessions` 表的不重複 `customer_id`（NULL 為訪客，自動排除）

```sql run
SELECT
  COUNT(DISTINCT session_id) AS sessions,
  COUNT(DISTINCT customer_id) AS logged_in_users
FROM sessions;
```

> [!BIZ] **已登入 vs 全部 Users**
>
> 本資料集只能識別已登入的 Users（有 `customer_id`）。實際 GA4 還會追蹤未登入的匿名訪客（用 `user_pseudo_id` cookie），不應據此推論與後台人數的大小關係。

> [!DIALECT] **BigQuery GA4：識別使用者**
>
> GA4 匯出的 BigQuery 資料中，識別使用者的欄位是：
> - `user_id`：已登入使用者的自訂 ID（對應 `customer_id`）
> - `user_pseudo_id`：GA4 自動產生的匿名識別碼（cookie）
>
> 以下只計匯出中可識別的裝置／應用程式實例 ID 與工作階段，不是所有自然人或報表 Active users：
> ```sql
> SELECT
>   COUNT(DISTINCT CONCAT(user_pseudo_id, '-', CAST(
>     (SELECT value.int_value FROM UNNEST(event_params) WHERE key='ga_session_id') AS STRING))) AS sessions,
>   COUNT(DISTINCT user_pseudo_id) AS observed_pseudo_users
> FROM `project.dataset.events_*`
> WHERE _TABLE_SUFFIX BETWEEN '20250701' AND '20260630'
> ```

## 計算 Pageviews

Pageviews 在 GA4 中是 `page_view` 事件的觸發次數，在本資料集對應 `events` 表中 `event_name = 'page_view'` 的筆數：

```sql run
SELECT
  COUNT(*) AS pageviews,
  COUNT(DISTINCT session_id) AS sessions_with_pageviews
FROM events
WHERE event_name = 'page_view';
```

## 按月統計三大指標

```sql run
SELECT
  strftime('%Y-%m', s.session_start) AS month,
  COUNT(DISTINCT s.session_id) AS sessions,
  COUNT(DISTINCT s.customer_id) AS logged_in_users,
  COUNT(CASE WHEN e.event_name = 'page_view' THEN 1 END) AS pageviews
FROM sessions s
LEFT JOIN events e ON s.session_id = e.session_id
GROUP BY month
ORDER BY month;
```

> [!TIP] **LEFT JOIN 讓每個 Session 都出現**
>
> 即使某個 session 沒有任何 event（理論上不應該，但資料可能有缺），LEFT JOIN 仍會把它計入 sessions 數。
> 用 INNER JOIN 則只計算有 event 的 session，會低估 sessions 指標。

## 流量來源分析

```sql run
SELECT
  source,
  medium,
  COUNT(DISTINCT session_id) AS sessions,
  COUNT(DISTINCT customer_id) AS logged_in_users
FROM sessions
GROUP BY source, medium
ORDER BY sessions DESC
LIMIT 10;
```

> [!DIALECT] **來源與 Users 口徑**
>
> traffic_source 是首次使用者來源；collected_traffic_source 是事件收集值；session_traffic_source_last_click 才是匯出的工作階段最後接觸來源。本課維度是模擬資料，不是上述欄位的直接複製。
>
> COUNT(DISTINCT customer_id) 只算已識別會員。COUNT(DISTINCT user_pseudo_id) 只算觀測到的裝置／應用程式實例識別碼；同一人跨裝置可能重複，缺少 ID 的事件被排除。原生 session 鍵使用 user_pseudo_id 與 ga_session_id 的組合，並排除缺鍵資料、揭露排除量；多資料串流分析亦應定義 stream_id 範圍。
>
> GA4 報表常見 Users 是 Active users；Total users 則是觸發任一事件的使用者，還涉及 reporting identity 等設定。本課缺少重建 Active users 的完整資料，不能把會員數或 pseudo ID 數直接視為後台 Users。
