## GA4 核心指標計算（二）：Session 深度與自訂單事件率

實務上要先區分 GA4 跳出率與本課可算的指標，否則會把不同口徑混為一談。

## GA4 跳出率不等於單事件率

GA4 互動工作階段符合任一條件：持續超過 10 秒（預設門檻，可調整）、發生關鍵事件，或至少 2 次頁面／畫面瀏覽。跳出率 = 非互動工作階段 / 全部工作階段 = 1 − 互動率。普通 scroll 或 click 本身不保證構成互動工作階段；is_active_user 是使用者層級資訊，不是工作階段旗標。

本資料集沒有完整互動時間、互動工作階段標記及關鍵事件設定，**不能還原 GA4 跳出率**。以下只算「自訂單事件率」：唯一事件為 page_view 的工作階段 / sessions 表所有工作階段。零事件工作階段仍在分母，但不在分子；這不是 GA4 指標。

## 計算每個 Session 的事件數（Session 深度）

```sql run
SELECT
  session_id,
  COUNT(*) AS event_count,
  COUNT(CASE WHEN event_name = 'page_view' THEN 1 END) AS page_views
FROM events
GROUP BY session_id
ORDER BY event_count DESC
LIMIT 10;
```

## 用 CTE 計算自訂單事件率

```sql run
WITH session_depth AS (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
),
single_event_flags AS (
  SELECT
    s.session_id,
    s.device,
    CASE WHEN COALESCE(sd.event_count, 0) = 1
              AND COALESCE(sd.pv_count, 0) = 1
         THEN 1 ELSE 0 END AS is_single_event
  FROM sessions s
  LEFT JOIN session_depth sd ON s.session_id = sd.session_id
)
SELECT
  COUNT(*) AS total_sessions,
  SUM(is_single_event) AS single_event_sessions,
  ROUND(SUM(is_single_event) * 100.0 / NULLIF(COUNT(*), 0), 1) AS single_event_rate
FROM single_event_flags;
```

> [!BIZ] **自訂單事件率高一定是壞事嗎？**
>
> 不一定。如果一篇部落格文章把答案寫得很清楚，使用者看完就滿足離開，自訂單事件率高反而是好事。
> 需配合交易、流量組成及埋點檢查；單事件率高或購買率低本身不能證明體驗有問題。

> [!DIALECT] **原生 GA4 的判定資料**
>
> 官方亦說明 is_engaged_session_event 用於改善互動率／跳出率計算。應依匯出中實際可用的互動工作階段相關參數（例如 session_engaged）及收集設定，在完整工作階段鍵上聚合，先檢查參數是否存在與型別；不能拿 scroll/click/purchase 白名單代替官方三項條件，也不能只靠最早與最晚事件時間保證重建互動時間。本課不提供無法用模擬資料驗證的 GA4 跳出率 SQL。

## 按裝置比較自訂單事件率

```sql run
WITH session_depth AS (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
),
single_event_flags AS (
  SELECT
    s.session_id,
    s.device,
    CASE WHEN COALESCE(sd.event_count, 0) = 1
              AND COALESCE(sd.pv_count, 0) = 1
         THEN 1 ELSE 0 END AS is_single_event
  FROM sessions s
  LEFT JOIN session_depth sd ON s.session_id = sd.session_id
)
SELECT
  device,
  COUNT(*) AS total_sessions,
  SUM(is_single_event) AS single_event_sessions,
  ROUND(SUM(is_single_event) * 100.0 / NULLIF(COUNT(*), 0), 1) AS single_event_rate
FROM single_event_flags
GROUP BY device
ORDER BY single_event_rate DESC;
```

## 平均 Session 深度

```sql run
SELECT
  ROUND(AVG(event_count), 2) AS avg_events_per_session,
  ROUND(AVG(pv_count), 2) AS avg_pageviews_per_session
FROM (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
);
```

> [!TIP] **CTE 讓計算分層更清晰**
>
> 複合指標（自訂單事件率、平均深度）的計算往往需要先在 session 層級彙總，再在整體層級統計。
> 用 CTE 把「計算 session 指標」和「彙總整體指標」分開，邏輯更清晰，也更容易加入 `WHERE` 篩選特定時段。
