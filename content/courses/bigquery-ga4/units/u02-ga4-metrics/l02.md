## GA4 核心指標計算（二）：Session 深度與跳出率

**跳出率（Bounce Rate）** 是 GA4 最受關注的指標之一。它告訴你有多少訪客「進來就走」，沒有任何互動。

## 什麼是跳出？

GA4（GA4 版本）對跳出的定義和舊版 Universal Analytics 不同：

| 版本 | 跳出定義 |
|---|---|
| Universal Analytics | Session 只瀏覽 1 頁就離開 |
| GA4 | Session 沒有任何「互動事件」（沒有捲動、點擊、購買等） |

本課用簡化定義：**session 只有 1 個 `page_view` 事件，且沒有其他事件**。

## 計算每個 Session 的事件數（Session 深度）

```sql run
SELECT
  session_id,
  COUNT(*) AS event_count,
  COUNT(CASE WHEN event_name = 'page_view' THEN 1 END) AS page_views
FROM events
GROUP BY session_id
ORDER BY event_count DESC
LIMIT 10;
```

## 用 CTE 計算跳出率

```sql run
WITH session_depth AS (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
),
bounce_flags AS (
  SELECT
    s.session_id,
    s.device,
    CASE WHEN COALESCE(sd.event_count, 0) = 1
              AND COALESCE(sd.pv_count, 0) = 1
         THEN 1 ELSE 0 END AS is_bounce
  FROM sessions s
  LEFT JOIN session_depth sd ON s.session_id = sd.session_id
)
SELECT
  COUNT(*) AS total_sessions,
  SUM(is_bounce) AS bounced_sessions,
  ROUND(SUM(is_bounce) * 100.0 / NULLIF(COUNT(*), 0), 1) AS bounce_rate
FROM bounce_flags;
```

> [!BIZ] **跳出率高一定是壞事嗎？**
>
> 不一定。如果一篇部落格文章把答案寫得很清楚，使用者看完就滿足離開，跳出率高反而是好事。
> 跳出率需要對比**轉換率**一起看：跳出率高 + 轉換率低 → 確實是問題。

> [!DIALECT] **BigQuery GA4：Engaged Sessions（互動工作階段）**
>
> GA4 原生提供 `is_active_user` 欄位，但要判斷「互動工作階段」，更常用的做法是：
> ```sql
> -- session 持續時間 > 10 秒，或有滾動/轉換事件
> SELECT
>   COUNT(DISTINCT session_id) AS engaged_sessions
> FROM (
>   SELECT
>     CONCAT(user_pseudo_id, '-',
>       (SELECT value.int_value FROM UNNEST(event_params) WHERE key='ga_session_id')) AS session_id,
>     MAX(CASE WHEN event_name IN ('scroll','click','purchase') THEN 1 ELSE 0 END) AS has_engagement
>   FROM `project.dataset.events_*`
>   GROUP BY session_id
> )
> WHERE has_engagement = 1
> ```

## 按裝置比較跳出率

```sql run
WITH session_depth AS (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
),
bounce_flags AS (
  SELECT
    s.session_id,
    s.device,
    CASE WHEN COALESCE(sd.event_count, 0) = 1
              AND COALESCE(sd.pv_count, 0) = 1
         THEN 1 ELSE 0 END AS is_bounce
  FROM sessions s
  LEFT JOIN session_depth sd ON s.session_id = sd.session_id
)
SELECT
  device,
  COUNT(*) AS total_sessions,
  SUM(is_bounce) AS bounced,
  ROUND(SUM(is_bounce) * 100.0 / NULLIF(COUNT(*), 0), 1) AS bounce_rate
FROM bounce_flags
GROUP BY device
ORDER BY bounce_rate DESC;
```

## 平均 Session 深度

```sql run
SELECT
  ROUND(AVG(event_count), 2) AS avg_events_per_session,
  ROUND(AVG(pv_count), 2) AS avg_pageviews_per_session
FROM (
  SELECT
    session_id,
    COUNT(*) AS event_count,
    SUM(CASE WHEN event_name = 'page_view' THEN 1 ELSE 0 END) AS pv_count
  FROM events
  GROUP BY session_id
);
```

> [!TIP] **CTE 讓計算分層更清晰**
>
> 複合指標（跳出率、平均深度）的計算往往需要先在 session 層級彙總，再在整體層級統計。
> 用 CTE 把「計算 session 指標」和「彙總整體指標」分開，邏輯更清晰，也更容易加入 `WHERE` 篩選特定時段。
