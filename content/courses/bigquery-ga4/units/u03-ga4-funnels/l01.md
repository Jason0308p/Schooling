## GA4 漏斗分析：從瀏覽到購買

轉換漏斗（Conversion Funnel）是 GA4 最核心的分析場景之一。它展示使用者在購買旅程中每個步驟的流失情況。

## 標準電商漏斗

本資料集的 5 個事件對應電商的完整購買旅程：

```
page_view → view_item → add_to_cart → begin_checkout → purchase
    ↓           ↓            ↓               ↓              ↓
  瀏覽頁面    看商品詳情    加入購物車       開始結帳        完成購買
```

## 建立基礎漏斗

```sql run
WITH funnel AS (
  SELECT
    CASE event_name
      WHEN 'page_view'      THEN 1
      WHEN 'view_item'      THEN 2
      WHEN 'add_to_cart'    THEN 3
      WHEN 'begin_checkout' THEN 4
      WHEN 'purchase'       THEN 5
    END AS step,
    event_name,
    COUNT(DISTINCT session_id) AS sessions
  FROM events
  WHERE event_name IN ('page_view','view_item','add_to_cart','begin_checkout','purchase')
  GROUP BY event_name
)
SELECT step, event_name, sessions
FROM funnel
ORDER BY step;
```

> [!BIZ] **為什麼用 COUNT(DISTINCT session_id)？**
>
> 同一個 session 可能觸發多次 `page_view`（使用者瀏覽了多頁），但在漏斗中這個 session 只應計為「1 個到達 page_view 階段的 session」。
> 用 `COUNT(*)` 會把同一 session 的多次事件都計入，導致漏斗頂部的數字虛高。

## 加入相鄰階段轉換率

```sql run
WITH funnel AS (
  SELECT
    CASE event_name
      WHEN 'page_view'      THEN 1
      WHEN 'view_item'      THEN 2
      WHEN 'add_to_cart'    THEN 3
      WHEN 'begin_checkout' THEN 4
      WHEN 'purchase'       THEN 5
    END AS step,
    event_name,
    COUNT(DISTINCT session_id) AS sessions
  FROM events
  WHERE event_name IN ('page_view','view_item','add_to_cart','begin_checkout','purchase')
  GROUP BY event_name
),
funnel_with_rate AS (
  SELECT
    step,
    event_name,
    sessions,
    LAG(sessions) OVER (ORDER BY step) AS prev_sessions
  FROM funnel
)
SELECT
  step,
  event_name,
  sessions,
  ROUND(sessions * 100.0 / NULLIF(prev_sessions, 0), 1) AS step_conv_rate
FROM funnel_with_rate
ORDER BY step;
```

> [!DIALECT] **BigQuery GA4：漏斗分析**
>
> BigQuery GA4 的事件資料格式相同，只是需要先攤平 `event_params`：
>
> ```sql
> -- BigQuery：先用 session_id 聚合，再建漏斗
> WITH sessions AS (
>   SELECT
>     user_pseudo_id,
>     (SELECT value.int_value FROM UNNEST(event_params) WHERE key='ga_session_id') AS session_id,
>     event_name
>   FROM `project.dataset.events_*`
>   WHERE event_name IN ('page_view','view_item','add_to_cart','begin_checkout','purchase')
> )
> SELECT
>   event_name,
>   COUNT(DISTINCT CONCAT(user_pseudo_id, CAST(session_id AS STRING))) AS sessions
> FROM sessions
> GROUP BY event_name
> ```

## 按裝置拆分漏斗

```sql run
SELECT
  s.device,
  e.event_name,
  COUNT(DISTINCT e.session_id) AS sessions
FROM events e
JOIN sessions s ON e.session_id = s.session_id
WHERE e.event_name IN ('page_view', 'add_to_cart', 'purchase')
GROUP BY s.device, e.event_name
ORDER BY s.device, e.event_name;
```

> [!TIP] **漏斗分析的實務重點**
>
> 光看轉換率數字不夠，要找到「為什麼流失」才能採取行動：
> - page_view → view_item 低：首頁或分類頁的商品展示不夠吸引人
> - view_item → add_to_cart 低：商品頁的說明、圖片、評價不足
> - add_to_cart → begin_checkout 低：可能有猶豫（等優惠碼、比較其他網站）
> - begin_checkout → purchase 低：結帳流程太複雜、沒有偏好的付款方式
